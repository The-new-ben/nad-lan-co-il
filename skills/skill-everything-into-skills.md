# Skill: Knowledge Capture Protocol (owner standing rule)
Every build, fix, research, or operational run on ANY site MUST end with a skill capture:
1. If a reusable pattern emerged -> write/update a skills/skill-*.md (what, why, exact steps,
   traps hit, code locations).
2. If research was done -> the cited doc goes in docs/ AND its actionable distillation goes into
   the relevant skill file.
3. Cowork/Codex runs: the final report includes a "SKILLS LEARNED" section; Claude commits them.
4. Skills are written site-agnostic (placeholders for site name/URLs) so they port to the next
   website (Justice legal portal and beyond) by copy.
5. For project-showroom work, update the specific showroom skills after every meaningful change:
   governance, premium showroom runbook, 3D model pipeline, interactive apartment picker, SEO
   assembly, and plugin release preflight.
6. Capture failures as aggressively as successes: version collisions, broken ZIP paths, missing
   module scripts, bad typography, missing OG images, invisible fields, and red QA gates are all
   reusable lessons.
7. A project is not "replicable" until a fresh agent can read the skills and know the fields,
   assets, QA commands, release sequence, and owner-only inputs required for the next project.
