## Per-image gate before any image enters nad-lan

Before an image from that folder is moved into the repo (`assets/images/`) or uploaded to the nad-lan WordPress media library, the operating agent (Codex) must record for each image:

1. **Filename** as stored.
2. **Generated by** (Codex prompt, date, model).
3. **Intended for which project** (only `nad-lan` is in scope here; reject others).
4. **Page / context** on nad-lan it serves (e.g. "Hero — homepage", "Pillar /investment — banner", "City page Tel Aviv — header").
5. **Alt text in Hebrew** (descriptive, not keyword-stuffed). See `copywriting-skill.md` §3.
6. **Hebrew filename or transliteration** for SEO friendliness, e.g. `hero-bayit-ba-tel-aviv.webp` not `image_0042.png`.
7. **Original dimensions and target dimensions** (target: max 1600px wide, WebP, quality 80).
8. **License / source confirmation**: was the image generated by Codex? If so, OK. If sourced elsewhere (Unsplash, Pexels, paid stock), record the licence URL.
9. **Faces / people**: if the image contains a recognizable person, do NOT use without confirming model release. AI-generated faces are usually OK but check for trademark/logo bleed.

Store this record in `docs/media-log.md` (append-only). Do not skip — when Yoast complains about missing alt later, or Google Lens identifies a non-licensed photo, this log is what saves the project.

## Image SEO rules (codified)

- File names in transliterated Hebrew or English. No `image_0042.png`.
- WebP only for new uploads. Fallback to JPEG only if a plugin demands it.
- Max 1600 px wide for hero, 1200 px for in-body, 400 px for thumbnails.
- Alt text describes the image, not the page topic. "מחשבון משכנתא" is not alt text for a stock photo of a calculator; "מחשבון משולחני על שולחן עץ" is.
- Use the `loading="lazy"` attribute on all in-body images (theme already supports `wp_enqueue_scripts` defaults; verify).
- Add `width` and `height` attributes to prevent CLS.
