# Lovable Execution Pack

Purpose: turn the NadLan strategy OS into a Lovable visual/product prototype that can guide real implementation.

This folder is for Lovable prompts and handoff, not production code.

## Source Project

Lovable URL:

`https://lovable.dev/projects/a7493b94-2e46-4d38-9c6a-80dcf0905f45`

Browser status from Codex on 2026-06-22:
- Direct Chrome navigation opened the project URL.
- The page shell initially exposed only "Skip to main content".
- A deeper browser screenshot/DOM capture timed out twice in the Chrome automation layer.
- Therefore, this pack is designed to be pasted into Lovable manually or through any available Lovable project prompt box.
- Do not treat hidden Lovable state as source of truth. If Lovable produces useful screens, export/copy the output back into this repo.

## Files

- `LOVABLE_MASTER_PROMPT.md` - paste-ready master prompt for Lovable.
- `SCREEN_MATRIX.csv` - exact screens/components Lovable must generate.
- `QA_AND_HANDOFF.md` - how to validate Lovable output and bring it back to repo.
- `REFERENCE_RESEARCH.md` - sources used to ground the Lovable workflow and real-estate UX.

## Success Definition

Lovable is successful only if it produces:

1. A consistent visual system using NadLan tokens.
2. A complete clickable/static gallery for the 15 required product screens.
3. Explicit official/concept/missing states for project media.
4. Responsive layouts at 1440, 768, and 390 widths.
5. No fake facades, no fake listings, no internal words, no silent fallback.
6. Exportable artifacts/screenshots committed back to the repo.

## Do Not Do

- Do not deploy Lovable output directly to production.
- Do not make Lovable the only source of truth.
- Do not create a fake real-estate product just because it looks nice.
- Do not publish generated facade/building assets as official.
- Do not hide broken/missing Mapbox, tour, or model states.
