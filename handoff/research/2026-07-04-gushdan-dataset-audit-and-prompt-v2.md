# Gush Dan dataset (ChatGPT batch) — critical audit + mega-prompt v2

Audited the uploaded `gush_dan_premium_new_projects_outputs_2026-07-03.zip`
(31 projects) against live sources. Verdict, then a rebuilt prompt that fixes
the failure modes.

## What I actually verified (not trusting the file)
- **All 31 official URLs return HTTP 200** and, on the sample I content-checked
  (Park Tower/hamavdil, Reading 22-24, Vertical City, Symphony Holon, Azorim
  Amos, Azorim Malachi, Rainbow), the page really is the claimed project. So the
  "many projects don't exist" fear is mostly **not** fabrication — the listed
  projects are real, active pages.
- **The excluded list (10) is honest** — every exclusion is a real sold-out /
  occupied / completed / rental project (Time Tower אוכלס, Yehuda Maccabi 49
  SOLD OUT, Da Vinci completed, etc.). Good judgement there.

## The REAL problems (these are why the file isn't usable as-is)

1. **GIS is systematically unreliable — confirmed on Rainbow.** Every `lat/lng`
   is a *manual eyeball pin typed by the model* (`lat_src: []`,
   `gis_note: "not official parcel-level geocoding"`). Rainbow is placed at
   **32.1298, 34.786** — that is ~2–3 km too far NORTH (up by Tel Baruch) and
   too far inland. Rainbow sits on the **former Sde Dov airfield / Eshkol
   quarter on the north-TA coast (~32.10 N)**. An LLM cannot geocode; this whole
   column must be regenerated by a real geocoder, not the model. (This is the
   exact "Rainbow is in the wrong place" the owner spotted.)
   - Related trap: several `address_he` values are the **sales-office** address,
     not the building parcel (the model flags this itself for Oliver, Malachi,
     Herzliya VILLE). Geocoding those would pin the wrong spot.

2. **Prices: 0% coverage.** The single most important buyer field is null for
   all 31. Honest (nothing invented) but useless for the product. New-project
   developer pages rarely publish prices — so price must come from Madlan / Yad2
   / gov transaction data (rmi/nadlan.gov.il) / press, which this pass didn't do.

3. **Under-delivered scope + scope drift.** 31 vs the 40–60 target, AND some of
   the 31 are **7-unit boutique buildings** (Amos, Malachi, Remez) that are NOT
   "premium/large/landmark" — the model admits this in its own notes. So the
   count is both short and diluted. The developer net was too narrow (5
   developers). Missing big players: Acro, Aura, Gindi, BSR, Rotshtein, Tidhar,
   Africa-Israel Residences, Y.H. Dimri, Almog/Almogim, Canada-Israel beyond the
   4 listed, Ashdar's full list, government pinui-binui megaprojects.

4. **Thin coverage overall — 41.9%.** floors, unit counts, building count,
   footprint, facade orientation, dist-to-sea all null for many. Two internal
   unit-count conflicts left unresolved (Rainbow 459 vs 480; i-Neot Afeka 22 vs
   23).

5. **No media.** No render image URLs, no floorplan URLs, no brochure PDFs — so
   nothing to feed a project page or the 3D/facade factory.

## Root cause → the fix
The model was asked to do two things it **cannot** do reliably: (a) geocode, and
(b) produce a full 60-project census in one pass. Split those out.

- **Never let the model output coordinates.** Have it output the **exact street
  address + gush/helka when the page states it + the official source quote**;
  OUR pipeline geocodes via govmap.gov.il / Mapbox / Google Places (deterministic,
  auditable). Confidence flag comes from the geocoder, not the model.
- **Prices come from a dedicated price pass** against Madlan / Yad2 / gov data,
  each with a source URL + as-of date, never the model's memory.
- **Run it developer-by-developer** (one prompt per developer catalogue) so each
  batch is small enough to verify every row, then merge. 60 projects in one
  prompt guarantees thin rows.
- **Hard inclusion gate:** status = בשיווק/active AND (≥ ~20 units OR a genuine
  landmark tower). Kills the boutique drift.
- **Require a verbatim quote** from the official page for every non-null
  structured field (floors, units, address) — the model already does `_src`
  URLs; add the exact quoted snippet so we can spot soft-404 / hallucinated
  numbers instantly.

## MEGA-PROMPT v2 (paste into ChatGPT/Gemini — run ONCE PER DEVELOPER)

> You are building a verified dataset of **premium new residential projects
> currently in active marketing (בשיווק) or under construction** in Gush Dan
> (Tel Aviv-Yafo, Ramat Gan, Givatayim, Bat Yam, Holon, Herzliya, Petah Tikva,
> Ramat HaSharon, Bnei Brak). This run covers **ONE developer: {DEVELOPER}**.
>
> INCLUSION GATE (all must hold): (1) status is actively marketing or under
> construction — quote the status text from the page; (2) it is premium AND
> either ≥ ~20 housing units OR a landmark high-rise/mega-complex. EXCLUDE
> sold-out, occupied (אוכלס), completed, or pure long-term-rental projects — but
> list them separately with the reason and source.
>
> FOR EACH INCLUDED PROJECT, from the developer's OFFICIAL page only, extract and
> for every structured value give BOTH the source URL AND a verbatim quoted
> snippet proving it:
> - name_he, name_en, developer, contractor, architect, marketing_status
> - **exact street address** (building, NOT the sales office — if the page only
>   gives a sales-office address, put it in `sales_office_address` and leave
>   `building_address` null; never guess). gush/helka if stated.
> - city, neighborhood
> - total_units, num_buildings, floors (min & max if a range), delivery_year
> - apartment mix / room types / sqm ranges if published
> - amenities list (pool, gym, lobby, ממ״ד, parking, etc.)
> - media: URLs of render images, floorplan images/PDFs, brochure PDF, video
> - official_url, madlan_url, yad2_url if present
>
> HARD RULES:
> - **Do NOT output latitude/longitude.** Geocoding is done downstream. Output
>   only the textual address + gush/helka + source. If you are tempted to
>   estimate coordinates, output null and add the address instead.
> - **Do NOT output prices** in this pass (separate pass). 
> - Never invent a value. Unknown = null. Never fabricate a URL — only paste
>   URLs you actually retrieved.
> - If two numbers conflict on the page (e.g. 459 vs 480 units), record both in
>   a `conflict` note with the two quotes; do not silently pick one.
> - Flag any page that is a soft-404, redirect to a catalogue, or sales-office
>   placeholder.
>
> OUTPUT: a JSON array of projects + a separate `excluded` array (name, reason,
> source, status-quote) + a `coverage` note listing which fields you could not
> fill and why. Return real downloadable files.

### Companion pass A — geocoding (OUR pipeline, not the model)
For each `building_address`: geocode via **govmap.gov.il** (authoritative
Israeli parcels) or Mapbox Geocoding; store lat/lng + `geocode_source` +
`geocode_confidence`. Cross-check the result city/neighborhood against the
project's; flag mismatches (this would have caught Rainbow instantly).

### Companion pass B — prices (separate model/API run)
Per project, pull an asking-price range from Madlan, Yad2, or
nadlan.gov.il/rmi transaction data, each with source URL + as-of date. Null if
none; never estimate silently.
