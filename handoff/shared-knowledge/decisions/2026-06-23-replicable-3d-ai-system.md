# Decision: Reusable 3D AI Site Transformation System

Date: 2026-06-23

Status: active

## Decision

The NadLan showroom/design/SEO process is now treated as a reusable system, not a one-off Lovable experiment.

Future real-estate WordPress projects should follow the same sequence:

1. repo and public-site inventory
2. source-context bundle
3. asset-truth matrix
4. showroom/listings/product architecture
5. multilingual SEO and anti-cannibalization map
6. design system and responsive specs
7. WordPress implementation backlog
8. screenshots and owner-readable HTML
9. repo-synced handoff and shared skills

## Reason

The owner wants to replicate this process across additional real-estate websites without depending on Lovable credits or chat-only memory.

## Operating Rule

Lovable is allowed to accelerate visual prototypes, but Codex must preserve the process in the repository and be able to repeat it independently.
