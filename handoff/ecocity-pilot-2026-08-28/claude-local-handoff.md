# מפרט העברה לקלוד: יישום מקומי בלבד

## מטרת המסירה

להקים בסביבת הפיתוח המקומית של `nad-lan.co.il` אב־טיפוס עובד לשני דפי־דגל:

- שטריקר 13–ברנדיס 14
- בני דן 54–56

מקור האמת העובדתי הוא התוכן העברי בחבילה, יחד עם `governance/fact-register.csv`. מטריצת השפות מגדירה התאמה מערכתית לאנגלית, צרפתית, רוסית וערבית. היא אינה מאגר עובדות עצמאי ואינה הרשאה לתרגום מכני או לפרסום.

## גבולות סמכות קשיחים

מותר:

- לקרוא את הריפו, את ההוראות המקומיות ואת חבילת הפיילוט.
- לפתוח branch מקומי חדש או worktree מבודד.
- לבנות, להריץ, לבדוק ולצלם תצוגה מקומית או preview מקומי מוגן.
- ליצור רכיבים, fixtures מסומנים, בדיקות ותיעוד מקומי.

אסור:

- לבצע push, merge, deploy, publish, שינוי WordPress, שינוי CMS או קריאת API כותבת.
- לשלוח ליד ל־CRM, לדוא״ל, ל־WhatsApp או לצד שלישי. טופס מקומי חייב להסתיים ב־mock sink בלבד.
- לשנות slug, canonical קיים, redirect, robots, sitemap או indexation.
- למחוק קבצים, עמודים, תוכן או נכסים.
- להשתמש במלאי, מחיר, תאריך, מרחק, סטטוס, תמונה, הדמיה, תכנית או מודל שאינם מאושרים לפי הרישומים בחבילה.
- להציג mock inventory כאילו הוא מידע אמיתי, גם אם הוא מסומן בקוד בלבד.

אם פעולה נדרשת חורגת מהגבולות האלה, עצור ודווח. אל תניח שהרשאה טכנית היא הרשאה עסקית.

## שלב אפס: הוראות Aurelia והגנת worktree

לפני שינוי קוד כלשהו:

1. קרא במלואם את `AGENTS.md` וכל קובץ הוראות רלוונטי לאורך העץ.
2. אתר וקרא במלואה את גרסת ה־Aurelia checklist הקנונית של הריפו. החבילה אינה כוללת אותה.
3. צור טבלת מיפוי קצרה בין סעיפי Aurelia לבין `qa/green-gates.md`.
4. במקרה של סתירה, בקשת המשתמש וה־Aurelia checklist הקנוני גוברים. תעד את ההכרעה ואל תרחיב סמכות.
5. תעד `git status --short --branch` לפני שינוי. אל תיגע בשינויים קיימים שאינם חלק מהמשימה.
6. עבוד על branch מקומי חדש, למשל `feat/ecocity-pilot-local`, או ב־worktree מבודד לפי כללי הריפו.
7. תעד את פקודות הבדיקה והקבצים ששונו. אין להריץ פקודות deploy או סנכרון מרוחק.

אם ה־Aurelia checklist אינו נמצא, עצור לפני שינוי קוד ובקש את מיקומו. אין להכריז על התאמה ל־Aurelia על בסיס מסמך השערים בלבד.

## סקר ריפו לפני מימוש

מבלי לשנות קוד, אתר ותעד:

- framework, build tool, router, מערכת locale ונתיבי הפרויקטים הקיימים.
- מקור התוכן הנוכחי של שני העמודים וכל רכיב משותף שהם צורכים.
- ספריית העיצוב, tokens, שיטות RTL/LTR וטעינת פונטים.
- תשתיות SEO, canonical, `hreflang`, JSON-LD, sitemap ו־preview `noindex`.
- ספק המפות, טפסים, consent, analytics, CRM וכל נקודת כתיבה חיצונית.
- תשתית התמונות, CDN, media manifest ורכיב/מנוע תלת־ממד, אם קיימים.
- בדיקות יחידה, אינטגרציה, נגישות, Lighthouse, visual regression ו־link checking.

הצג מיפוי של “קיים”, “ניתן לשימוש חוזר”, “דורש שינוי” ו“חסום” לפני בנייה.

## מימוש תוכן ונתונים

- התייחס ל־`content.he.json` כטיוטת נתונים מאומתת סכמטית, ולמסמך העברי כמקור העריכתי המלא.
- אמת את שני קובצי ה־JSON מול `schemas/project-content.schema.json` בזמן build או CI.
- בנה שכבת fact resolver: כל טענה עובדתית שמוצגת חייבת להפנות ל־`fact_id` קיים ומותר לפרסום.
- `VERIFIED_PRIMARY` מותר להצגה בניסוח זהיר; `TIME_SENSITIVE` מותר רק בתוך חלון הרענון; `DEVELOPER_CLAIM` חייב להישאר מיוחס ליזם.
- `SECONDARY_CONFIRM`, `CONFLICT`, `MISSING` ו־`BLOCKED_RIGHTS` לא יוצגו כעובדות. null וערך חסר יושמטו, לא יוחלפו בניחוש.
- מספרים, תאריכים, שמות ישויות וסטטוסים בארבע השפות הנוספות חייבים להיות נגזרים ממקור האמת העברי ומרישום העובדות.
- אין להעתיק תוכן מעמודי הנדל״ן הקיימים כאשר הוא כולל מחיר, מרחק, מונה יחידות או סטטוס שאינם מאושרים ברישום.
- הצג תאריך בדיקה אחרון ומגירת מקורות נגישה במקום המתאים בעיצוב.

## עמודים ושפות

- בנה shell משותף ורכיבי תוכן מודולריים, אך אפשר הבדלים מהותיים בין שני הפרויקטים.
- יישם את ארכיטקטורת העמוד ב־`product/page-and-3d-spec.md`, עם HTML בסיסי שימושי ללא JavaScript.
- עברית וערבית הן RTL; אנגלית, צרפתית ורוסית הן LTR. אל תסובב אייקונים בעלי משמעות כיוונית באופן גורף.
- השתמש במטריצת ההתאמה לתוכן ברמת כותרת, תקציר, CTA, הסברים וקול. אין להציג את ארבע השפות כמאושרות לפרסום לפני ביקורת עורכים דו־לשוניים.
- ודא ששמות רחובות, מספרי כתובת ומונחים ישראליים נשארים עקביים בכל השפות.
- הסבר את מוסכמת “מספר חדרים” הישראלית רק כאשר יוצג בפועל מידע מאושר על תמהיל דירות.
- `hreflang` יופעל רק עבור גרסאות שבאמת קיימות ומקבילות; preview מקומי אינו משנה canonical או sitemap חי.

## מפת מקום ו־POI

- הצג אזורים וקטגוריות, לא מרחקים או זמני הליכה שאינם מאומתים.
- תוויות “מתוכנן”, “קיים” ו“לבדיקה” חייבות להיות מובחנות בקוד ובממשק.
- הרכבת הקלה תתואר כתשתית עתידית/מתוכננת לפי המקור הרשמי, ללא תאריך פתיחה או טענת קרבה מדויקת.
- בני דן משויך בהקשר המקומי לפארק הירקון; אין להפוך “קו ראשון” או נוף פתוח להבטחה קבועה.
- פארק וחוף הם קטגוריות שונות. אין להסיק קרבה לחוף בלי מדידה ומקור מאושרים.
- ספק חלופה טקסטואלית מלאה לכל מפה אינטראקטיבית.

## מדיה ותלת־ממד

- התחל ב־media shell ללא asset אמיתי. כל asset חייב לעבור דרך `governance/media-rights-ledger.csv` ולהיות במצב `APPROVED` ולא פג תוקף.
- אל תוריד, תעתיק, תחתוך, תשפר או תטמיע תמונות מאתר EcoCity או ממקור אחר בלי אישור שימוש כתוב.
- רכיב התלת־ממד חייב להיות progressive enhancement. טבלת בניינים/קומות/יחידות נגישה נשארת מסלול מלא ועצמאי.
- אין לבנות גאומטריה ייצוגית “בקירוב”. עד לקבלת set אדריכלי, צפון אמת, datum, מזהי יחידות וזכויות, הצג placeholder לא־פוטוריאליסטי שאינו מתיימר להציג את הבניין.
- אל תציג “נוף מהדירה”, “נוף אמיתי”, ים, קו רקיע, בניינים שכנים, צמחייה או אור שמש כסימולציה עובדתית ללא manifest מאושר.
- טען WebGL רק בעקבות כוונת משתמש ובכפוף לתקציבי הביצועים. כשל WebGL, reduced motion ומקלדת חייבים לעבור למסלול החלופי.

## טופס והמרה

- יישם טופס אב־טיפוס עם שדות מינימליים ו־mock sink מקומי שאינו שולח נתונים.
- CTA צריך לשקף פעולה אמיתית: בקשת מידע עדכני או שיחה עם נציג האתר, לא “שמירת דירה” או הבטחת מענה מהיזם.
- הצג עצמאות מערכתית של nad-lan.co.il ולא רמז לשותפות/בלעדיות ללא אישור.
- הסכמה שיווקית אופציונלית, נפרדת ולא מסומנת מראש. טקסטים משפטיים בחמש שפות נשארים חסומים עד אישור.
- אל תכניס PII ל־URL, analytics, logs או storage. בדיקות מקומיות ישתמשו בנתוני fixture סינתטיים בלבד.

## SEO, נתונים מובנים ומדידה

- יישם את `WebPage`, `ApartmentComplex` ו־`BreadcrumbList` רק מתוך עובדות ירוקות וגלויות בעמוד.
- `FloorPlan` ו־`RealEstateListing` מותנים ברישומי תכניות/יחידות מאושרים. `Offer`, מחיר, זמינות, דירוג וביקורת אינם מותרים במצב הנוכחי.
- JSON-LD אינו מקום להחביא מידע שחסר מן העמוד או לעקוף חסם תוכן.
- יישם את חוזה האירועים שבמפרט ללא PII, עם consent ועם מניעת אירועים כפולים.
- אירועי יחידה מותרים רק לאחר חיבור inventory מאושר; אין ליצור IDs אנליטיים ליחידות מדומות.
- מדוד LCP, INP ו־CLS בנפרד לפי project ו־locale. נתוני lab יוצגו כ־lab בלבד.

## בדיקות נדרשות

לפחות:

- schema validation לשני קובצי התוכן.
- fact-ID resolution, freshness, suppression ו־locale numeric/entity parity.
- HTML snapshot ללא JavaScript ובלי WebGL.
- RTL/LTR, mixed-direction strings, keyboard, focus, reflow ו־screen-reader smoke test.
- WCAG 2.2 AA: בדיקות אוטומטיות ובדיקות ידניות מתועדות.
- canonical/`hreflang`/structured-data tests בסביבת preview, בלי שינוי indexation.
- internal-link check, forbidden-claim lint ו־media-rights build gate.
- form success/error with mock sink, no network write and no PII analytics.
- viewer lazy-load, WebGL failure, reduced motion והחלופה הטקסטואלית.
- visual regression בחמש השפות וברוחבי mobile, tablet ו־desktop.
- תקציבי ביצועים ו־Core Web Vitals מקומיים, עם הבחנה בין shell לבין viewer.

7. טופס mock, analytics consent-safe ובדיקות.
8. הרצת G0–G12 ועדכון `qa/green-gates.md` עם ראיות. G13 נשאר אדום.

## פורמט דוח הסיום לקלוד

יש להחזיר:

- branch/worktree ושורת מצב לפני ואחרי.
- סעיפי Aurelia שחלו והראיה לכל אחד.
- קבצים שנוספו/שונו, עם הסבר תמציתי.
- פקודות בדיקה ותוצאות, כולל כשלים שנותרו.
- טבלת G0–G13 מעודכנת עם קישור או נתיב לכל ראיה מקומית.
- רשימת עובדות/נכסים/אישורים שעדיין חסרים.
- צילומי מסך מקומיים רלוונטיים אם כלי הריפו תומכים בכך.
- הצהרה מפורשת שלא בוצעו push, deploy, publish, redirect, deletion או שליחת ליד.

המימוש אינו “מוכן לפרסום” כל עוד G13 אדום, גם אם G0–G12 ירוקים.
