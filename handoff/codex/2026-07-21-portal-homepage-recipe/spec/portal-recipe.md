# Canonical Portal Recipe

## Product promise

**Hebrew:** פורטל הפרויקטים והנדל״ן בישראל שמאפשר לראות, להשוות ולבדוק לפני שפונים.
**English:** Israel's project and property portal for seeing, comparing and checking before you inquire.

The surface is deliberately familiar. The depth is where NadLan wins: approved media, project/unit structure, source/date visibility, area evidence, plans, 3D when genuinely available, a foreign-buyer operating layer and a clearly identified human contact.

## The “50-year institution” test

A visitor should understand these facts in five seconds without reading a manifesto:

1. There is real inventory to browse.
2. The portal covers recognizable places, projects and developers.
3. Cards contain current, comparable facts.
4. Images are real or honestly labelled.
5. Search, map, save, compare and contact are normal working product actions.
6. Deeper evidence exists after the click.
7. The company knows who owns, sourced and last checked the information.

Institutional authority may be reinforced with true history, counts, editorial freshness and named experts. It may never be simulated with invented years, inventory totals, awards or visitor numbers.

## The canonical visual formula

| Layer | Rule |
| --- | --- |
| Identity | Keep NadLan's cream/ink foundation, restrained gold structure and occasional terracotta action color |
| Typography | Frank Ruhl Libre for Hebrew display; Heebo for Hebrew UI/body; matching editorial/sans pair for English |
| Imagery | Wide approved project photography/renderings first; 4:3 card crops; real interiors and context; sketches only for explanatory/editorial support |
| Density | Many useful doors and cards, but grouped into clear rails with consistent card grammar |
| Borders/radius | Fine rules and modest radii; avoid bubbly app styling and oversized rounded containers |
| Motion | Quiet hover/focus feedback; no autoplay visual spectacle; 3D opens only when requested |
| Badges | Maximum three high-value badges on a card; overflow becomes “more”; every badge has evidence |
| Mobile | One-column image-first cards, horizontal rails only when discoverable, persistent single contact action, no overlay pile-up |

## Twelve homepage zones

This retains the July 2 CMS-driven, 12-band structural canon while updating the visual priority to real assets and portal density:

1. Verified market utility strip.
2. Header and keyboard/mobile-accessible mega navigation.
3. Image-led search hero.
4. Trust/current-market snapshot.
5. Featured new projects.
6. Active property/project inventory rail.
7. Popular cities and compounds.
8. Recently verified / newly updated projects.
9. Market intelligence and practical tools.
10. Guides, news and named expertise.
11. Foreign-buyer and remote-purchase entry.
12. Institutional mega footer.

All zones are CMS-owned, reorderable and allowed to collapse when their data-quality gate fails. There is no hardcoded fake substitute.

## Card grammar

```text
approved image / honest illustrative state
→ lifecycle + proof badges
→ project name
→ developer
→ city / neighborhood
→ approved price wording
→ rooms / size / handover / construction state
→ source + last verified
→ save / compare / view project / contact
```

Project and ordinary property cards must not be flattened into one schema. A project card represents a development and may link to plans/units. A property card represents one property/listing. A unit card represents a specific unit/plan and inherits the project identity.

## Badge families

| Family | Examples | Rule |
| --- | --- | --- |
| Lifecycle | Pre-sale, marketing, under construction, occupied | One primary state from approved structured field |
| Trust | Ownership verified, information verified, media approved | Only after workflow evidence exists |
| Media | 3D, floorplans, video, gallery count | Only when the specific media is publishable and working |
| Commercial | Payment plan, request price, limited release | Source/date required; commercial wording is volatile |
| Audience | Foreign-buyer ready, English sales contact | Requires the full readiness checklist, not translation alone |
| Placement | Sponsored/promoted | Always explicit; never used as a quality or verification badge |

## What makes NadLan different

The portal should not lead with “we have 3D.” It should lead with projects and decisions. 3D becomes a meaningful proof/action inside eligible cards and project pages.

NadLan's defensible combination is:

- familiar portal discovery;
- structured Israeli new-project depth;
- real transaction/area context with source/date;
- media and fact provenance;
- exact freshness behavior;
- HE/EN foreign-buyer operations;
- unit-aware 3D when official data makes it true;
- verified professionals connected to the buying decision.

## Inventory quality states

| State | Public behavior |
| --- | --- |
| Incomplete | Draft/private; never used to create a public empty card |
| Basic verified | Public searchable card with approved hero, identity, location, status, source/date and contact |
| Visual complete | Basic + gallery + logo + plan/spec assets and media rights |
| Lead ready | Visual complete + current commercial language + named routing owner + tested form/WhatsApp |
| Foreign ready | Lead ready + English parity + currency/units + process/cost content + remote contact workflow |
| Digital showroom | Lead ready + approved model/facade/unit data + plans/views + honest 3D evidence |

Payment tier and content quality are separate. Paid placement can change exposure only after the record passes the minimum public-quality gate.

## Business model fit

- Buyers receive usable comparison, evidence and a confident contact path.
- Developers claim and complete project pages, provide rights-cleared media and receive contextual inquiries.
- Professionals appear at relevant decision points with explicit sponsored labels where applicable.
- NadLan sells exposure and enhanced project experiences, never verification itself.
- The portal earns long-term authority through complete city/project/developer graphs and regularly verified data.

## Non-goals for the first approved implementation

- Rebuilding WordPress as a detached SPA.
- Rendering a heavy live 3D model above every fold.
- Inventing national inventory scale before records pass quality review.
- Publicly exposing demo/test projects.
- Five unrelated visual concepts.
- Automated price, legal or availability claims without a source and owner.
- Exact window/unit selection without official geometry and identifiers.

## Phased delivery after owner approval

1. **Content readiness:** choose the launch cohort and obtain approved assets/facts.
2. **WordPress contract:** approve any missing fields, roles, states and review cadence.
3. **Card/catalog:** build one stable project-card component and list/map behavior.
4. **Project mini-site:** ship media/facts/map/contact first; progressively add unit and 3D depth.
5. **Homepage:** assemble CMS-driven zones from the same approved records.
6. **Foreign layer:** finish true HE/EN parity and remote-buyer workflow.
7. **Outreach:** approach developers only when the public product passes the presentation gate.
