# Presentation Readiness Gate

## Current verdict from available evidence

**Not ready for an external developer/investor presentation yet.**

This is not a judgment that the product lacks substance. The repository contains substantial WordPress, catalog, lead, data and 3D infrastructure. The presentation risk is that the visible experience can still expose sparse inventory, missing featured images, prototype project media, inconsistent facility fields and unverified/stale commercial facts. Those signals make a capable system look unfinished.

The five review pages in this package show the target. They do not change the live verdict and use illustrative repository assets.

## Presentation minimum

The exact launch cohort is an owner decision. The recommended minimum to avoid repetition/empty rails is:

- 12 distinct visual-complete projects for homepage/catalog presentation;
- 3 flagship lead-ready project mini-sites;
- 6 foreign-ready projects if the English investor proposition is shown;
- 4 non-empty city/compound hubs;
- 1 complete developer profile/portfolio example;
- working search, map, save, compare and contact evidence;
- no public demo/test records.

These are readiness thresholds, not claims about current inventory.

## Gate A — visual credibility

- [ ] Approved hero and card image for every above-the-fold project.
- [ ] No generic concept image presented as an actual project/unit.
- [ ] Consistent card ratio/crop and visible image count.
- [ ] Rendering/illustrative labels are correct and readable.
- [ ] Developer logos and plans have permission.
- [ ] Desktop and mobile crops reviewed.

## Gate B — portal density and navigation

- [ ] Search-first first viewport.
- [ ] Distinct project cards; no language duplicates.
- [ ] Active rails have enough eligible records or collapse.
- [ ] City/compound cards lead to useful hubs.
- [ ] Mega navigation/footer contain real destinations.
- [ ] Editorial/tools support inventory rather than conceal thinness.

## Gate C — facts and freshness

- [ ] Project/developer/location identity verified.
- [ ] Stage/handover/price policy carry source and check date.
- [ ] Exact price/availability is current or replaced by confirmation wording.
- [ ] Every badge passes its evidence contract.
- [ ] Counts are query-generated and current.
- [ ] Conflicts are resolved or visibly explained.

## Gate D — project depth

- [ ] Gallery/media tabs contain real publishable items.
- [ ] Unit/plan language matches the actual data level.
- [ ] Facilities are structured and evidenced.
- [ ] Map point/layers are sourced.
- [ ] Developer/team/contact are named and linked.
- [ ] Inquiry preserves project/unit/language context.
- [ ] 3D promise matches model/geometry capability.

## Gate E — foreign-buyer readiness

- [ ] English is complete, not a machine-translated shell.
- [ ] Currency/unit conversion is dated and identified as indicative.
- [ ] Buying process and total-cost guidance exist with caveats.
- [ ] Remote viewing/contact path has a named English-speaking owner.
- [ ] Equivalent HE/EN page switching works.
- [ ] Foreign-ready badge is produced only by the full checklist.

## Gate F — WordPress operations

- [ ] The same WordPress record powers all surfaces.
- [ ] Developer claim/Studio path is tested.
- [ ] Media rights approval is separate from upload.
- [ ] Critical field changes are auditable/revision-aware.
- [ ] Stale data enters review and degrades safely.
- [ ] No application password, secret or private note is exposed.
- [ ] Sponsored and verified status are independent.

## Gate G — experience quality

- [ ] 1440px desktop review.
- [ ] 390px mobile review with no page-level overflow.
- [ ] HE RTL and EN LTR.
- [ ] Keyboard/focus behavior and form labels.
- [ ] Normal text contrast 4.5:1; large text 3:1.
- [ ] Primary controls meet the 44×44px internal target.
- [ ] LCP/INP/CLS targets measured on the implemented pages.
- [ ] Hero loads without autoplay video/heavy 3D.

## Recommended presentation story

1. **Start with the portal:** familiar search, rich inventory and map.
2. **Open one flagship project:** media, facts, plans, facilities, source/date and contact.
3. **Show the differentiator:** unit-aware 3D only on a project whose source data supports it.
4. **Switch to English:** show that foreign readiness is a full workflow.
5. **Show the developer loop:** claim, complete, approve, publish and receive contextual inquiries.
6. **Close with governance:** WordPress ownership, rights, freshness and scalable project onboarding.

Do not start the presentation with architecture diagrams, prototype disclaimers or an explanation of what will eventually exist. Those belong in diligence after the product has made a strong visual first impression.

## Owner decision required before implementation

- Approve the canonical five-view system.
- Select the launch cohort.
- Obtain/approve the media pack and facts.
- Approve field/workflow additions.
- Approve a separate implementation branch.
- Approve staging deployment and QA before any live change.
