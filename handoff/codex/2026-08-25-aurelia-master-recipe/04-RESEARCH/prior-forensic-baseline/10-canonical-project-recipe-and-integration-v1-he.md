# מתכון עמוד הפרויקט הקאנוני וחוזה החיבור לאתר — v1

תאריך: 25.08.2026
סטטוס: מעבדת בעלים פרטית; לא בוצע שינוי ב־WordPress או באתר הציבורי.

## 1. ההחלטה הארכיטקטונית

המעבדה אינה מוצר מקביל ואינה מציעה Backend חדש. היא שכבת תצוגה ומתכון בדיקה חדשים מעל המערכת שכבר קיימת:

- WordPress נשאר מקור האמת של נתוני הפרויקט.
- `window.NADLAN_SHOWROOM` נשאר ה־payload הציבורי שממנו מנוע השואורום מצייר את הפרויקט.
- מזהה דירה קיים, למשל `duo-a-21`, נשמר ללא תרגום בכל מסך ובכל בקשה.
- `engine.js`, `buyflow.js`, `studio.js` ו־`mapbox-init.js` נשארים בעלי היכולות הקיימות.
- `unit-sheet.js` מוגדר כרכיב מעבר משום שהוא נטען רק בחלק מהפרויקטים.
- ה־UI החדש מתחבר לפעולות הקיימות באמצעות אותם `data-act`, `data-id` ו־`data-tool`.
- אין להפעיל במקביל שני מאזיני click על אותו כפתור. בהטמעה ב־WordPress, שכבת המתאם מוסרת את handler המעבדה ומעבירה בעלות למנוע הקיים, או עוצרת propagation ומפעילה פעולה אחת בלבד.

## 2. חוזה החיבור — לחיצה מול המנוע הקיים

| כוונת המשתמש | markup קיים שנשמר | הנתון שחייב לעבור | בעל היכולת הקיים |
|---|---|---|---|
| בחירת דירה | `data-act="select" data-id="<unit-id>"` | Unit ID מקורי | `engine.js` |
| פתיחת תוכנית | `data-act="unit-tool" data-tool="plan"` | Unit ID הפעיל | `engine.js` + drawings |
| פתיחת נוף ואלומה | `data-act="unit-tool" data-tool="view"` | Unit ID, קומה, כיוון | `engine.js` + `mapbox-init.js` |
| סיור פנים | `data-act="unit-tool" data-tool="tour"` | Unit ID ו־tour/panorama | `engine.js` |
| פתיחת סטודיו דירה | `data-act="studio" data-id="<unit-id>"` | Unit ID ומפרט | `studio.js` |
| בקשת תוכניות ומחירים | `data-act="rfp" data-id="<unit-id>"` | Project ID, Unit ID והקשר המסע | `buyflow.js` |
| פתיחת Co-tour | `data-act="cotour"` | room + מצב השואורום | `engine.js` |
| בחירת נקודת סביבה/מתקן | `data-act="pin" data-id="<ref>"` | environment/facility ref | `engine.js` + `mapbox-init.js` |

## 4. Endpoints שנשמרים

- `POST /wp-json/nadlan/v1/lead` — ליד עם הקשר הפרויקט והיחידה.
- `GET /wp-json/nadlan/v1/brochure?p=<project>&u=<unit>&lang=<lang>` — חוברת/תוכנית.
- `POST + GET /wp-json/nadlan/v1/cotour` — חדר צפייה משותפת.

חוזה ה־Co-tour הקיים נשמר: `?cotour=host|join&room=<code>`, עדכון כל 1.6 שניות, וסנכרון מצלמה, יחידה, תאורה, שמש, פילטר ותצוגה. המעבדה מדמה את הזרימה בלבד ואינה שולחת דבר ל־production.

## 5. הסדר הקאנוני של חוויית הרוכש

1. זהות: פירורי לחם לחיצים, eyebrow, H1 יחיד והבטחת ערך.
2. פעולה מיידית: בחירת דירה או שיחה — לפני תוכן ארוך.
3. progress bar: מצב הפרויקט מוצג לפני השואורום, משום שהוא משנה את רמת הסיכון והדחיפות.
4. מלאי קצר: סינון חדרים ובחירת יחידה באמצעות אותו Unit ID.
5. במה מרכזית: בניין עם hotspots גלויים בגודל 44×44 לפחות.
6. כרטיס יחידה קבוע ונמוך: קומה, חדרים, שטח, מרפסת וכיוון; אינו מזיז את הבניין לאחר בחירה.
7. כלי החלטה לפי היחידה: תוכנית, נוף, פנים, מתקנים וסביבה.
8. בקשה לתוכניות ומחירים: ההקשר של היחידה נשמר אוטומטית.
9. Co-tour/פגישה: המשקיע יכול לצפות יחד עם נציג, יזם ואיש מקצוע.
10. בהמשך העמוד: תוכן עומק, עסקאות, סביבה, יזם ואנשי מקצוע. אורכו מנוהל לפי דרישת המערכת, כולל יעד 5,000 מילים כשנבחר.

## 6. מצב המעבדה המלא

בצד הרוכש אין מצבי “מחכים לחומרים”, “יוצג בהמשך” או שדות ריקים. נוצרו והוטמעו:

- הדמיית חוץ של שני המגדלים;
- תוכנית דירה מרוהטת;
- נוף מרפסת/חלון;
- הדמיית פנים;
- הדמיית מתקנים;
- הדמיית סביבה אווירית.

כל חומר generated מסומן פעם אחת ובצנעה כ־“הדמיה להמחשה”. מחירים מוגדרים כאומדן כברירת מחדל. מצבי `missing`, שגיאה וטעינה קיימים רק בתוך מנגנון הבדיקה הפנימי כדי שאפשר יהיה לבדוק אותם בלי להציגם לקהל.

## 7. מנגנון הצ׳ק־ליסט

המתכון אינו רשימה שטוחה. כל תבנית בדיקה מוכפלת רק במטריצות שרלוונטיות לה:

- מצב: default, hover, focus, pressed, loading, success, error, empty, missing-data ועוד;
- מכשיר: טלפונים צרים ורחבים, טאבלט, לפטופ ודסקטופ;
- שפה: עברית, אנגלית, צרפתית, רוסית וערבית;
- ראיה: שדה WordPress, payload ציבורי, Source גולמי, DOM חי, צילום, replay או analytics.

בגרסה הנוכחית נוצרו 2,200 בדיקות אטומיות מ־22 משפחות. הנורות ירוקות, צהובות, כתומות ואדומות — הן אינן חוסמות פרסום. כל נורה נפתחת לראיה פעילה.

## 8. Source ציבורי

ה־Cockpit קורא בזמן אמת את ה־HTML הציבורי של DUO ומציג:

- HTTP, גודל, זמן, SHA-256 ותאריך איסוף;
- title, description, canonical, robots, H1/H2 ומספר מילים;
- favicon declarations, JSON-LD, קישורי `href="#"`, כותרות כפולות ומיקום דיסקליימר;
- רשימת scripts;
- הימצאות `window.NADLAN_SHOWROOM` ושורתו ב־Source;
- סקריפטי מנוע השואורום שנטענו בפועל.

בבדיקה האחרונה: HTTP 200, title באורך 59, H1 יחיד, 5,188 מילים ו־25 scripts. נמצאו ארבע הכרזות favicon והדיסקליימר מופיע לפני ה־H1 באותו Source — שתיהן נורות כתומות, לא חסימות.

## 9. בדיקות שבוצעו

- TypeScript נקי ובניית production מלאה עברה.
- מובייל 390×844 ודסקטופ 1280×495 נבדקו ללא overflow אופקי של המסמך.
- hotspots בגודל 44×44; הנקודה הנבחרת 49×49.
- בחירת יחידה מתקנת גלילה כך שהבניין והכרטיס נשארים יחד באזור הראייה.
- כל שש הסצנות נטענו עם הנכס הנכון.
- בחירת חלל פנים, מתקן ונקודת סביבה משנה מצב גלוי.
- מסלול ליד, תיאום פגישה ו־Co-tour הושלמו במעבדה עם Unit ID והקשר הסצנה.
- ארבע לשוניות ה־Cockpit — נורות, Source, Recipe וחיבור — נבדקו בפועל.

## 10. הוראת מסירה לצוות

1. אין להעתיק את המעבדה כתבנית WordPress שלמה.
2. מתחילים ב־adapter: ממירים את `window.NADLAN_SHOWROOM` ל־props של רכיבי התצוגה בלי לשנות את הנתונים.
3. מחברים כל פעולה ל־`data-act` הקיים ומוודאים שאין double binding.
4. מתחילים בפרויקט ניסוי אחד וב־feature flag פרטי.
5. בודקים את אותו Unit ID ב־WordPress, ב־payload, ב־DOM, ב־lead וב־Co-tour.
6. מצלמים Source ציבורי לפני ואחרי ושומרים SHA ודיפרנציאל.
7. משחררים רק את הניסוי; לא מאחדים את יתר הפרויקטים לפני שמתקבלות תוצאות שימוש ולידים.
