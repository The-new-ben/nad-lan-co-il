# המסקנה העיקרית שלי

אתה צודק שהדיון סטה יותר מדי לניקוי טכני. הבעיה העסקית המרכזית אינה שחסרים עוד תיאורי מטא. הבעיה היא שהאתר מחזיק מוצר טוב מאוד, בחירת פרויקט ודירה בתוך חוויית תלת־ממד, אבל רוב צי הפרויקטים אינו מוכיח כרגע את אותה הבטחה.

האתר צריך להיות מוגדר כך:

> **NadLan הוא מערכת לבחירה ולקבלת החלטות בפרויקטים חדשים: חיפוש, מידע מאומת, סביבת מגורים, תלת־ממד, בחירת יחידה, תוכנית, נוף ופנייה שמכילה את הדירה שהרוכש בחן.**

היתרון העסקי אינו מספר הפרויקטים לבדו. היתרון הוא המסלול:

```text
חיפוש
→ עמוד פרויקט
→ הפעלת Viewer
→ בחירת בניין
→ בחירת יחידה
→ פתיחת תוכנית או נוף
→ בקשת פרטים
→ ליד עם project_id ו-unit_id
→ אישור קליטה ב-CRM
→ שיחה
→ פגישה
→ עסקה מיוחסת
```

כל רכיב באתר צריך להיבחן לפי השאלה אם הוא מחזק את המסלול הזה.

# התיקון החשוב לצ׳ק־ליסט של קלוד

לקחתי את ה־v1 של קלוד ושמרתי את החלקים הטובים שבו: mobile first, בניין בפולד הראשון, H1 אחד, אפס טקסטי המתנה, deep links, console נקי, תוכנית לכל יחידה ובדיקה לפני ואחרי פתיחת הכרטיס.

אבל תיקנתי כמה כללים שהיו עלולים ליצור בעיה חדשה.

## 1. אסור למלא חוסר עובדתי בג׳נרציה

הכלל הנכון הוא:

- `unknown` מושמט;
- המחשה יכולה למלא חלל חזותי;
- המחשה לעולם אינה הופכת למחיר, תוכנית, נוף, מלאי, כיוון או סטטוס;
- תוכנית גנרטיבית אינה תוכנית דירה;
- פנים גנרטיבי אינו תיאור של מפרט היזם;
- נוף משוער חייב להיות מסומן כהמחשה ולא כמבט אמיתי מהיחידה.

כלומר, “אפס טקסטי המתנה” כן. “להמציא משהו במקום” לא.

## 2. אין תקרת 1MB אוניברסלית למודל

במקום כלל שרירותי יש תקציב מדורג:

- poster קל;
- מעטפת ראשונית;
- פרטים וטקסטורות לפי צורך;
- פנים רק לאחר בחירת יחידה;
- מדידת transfer, זיכרון מפוענח, textures, triangles, draw calls ו־time-to-interactive.

מודל קטן מאוד יכול להיות גרוע אם הוא מפענח טקסטורות כבדות או יוצר עומס GPU. הציון מבוסס על חוויית המשתמש והביצועים בפועל.

## 3. אין חובה ל־5,000 מילים בכל פרויקט

הצי חולק לארבע רמות:

| רמה | תפקיד |
|---|---|
| R0 | רשומת מידע בסיסית ומדויקת |
| R1 | פרויקט מאומת עם סביבת החלטה ותוכן משמעותי |
| R2 | פרויקט עם חוויית תלת־ממד עובדת |
| R3 | בחירת יחידה, מלאי, תוכניות וליד מחובר ל־CRM |

5,000 מילים מתאימות רק כאשר יש תכנון, עסקאות, נתוני סביבה, יחידות, מקורות וניתוח שמצדיקים אותן. ניפוח אוטומטי של כ־1,000 פרויקטים ייצור צי טקסטים דומים במקום נכס אורגני.

## 4. מחיר אינו שדה חובה

מחיר מוצג רק עם:

```text
price
price_type
source
source_date
unit_or_project_scope
currency
limitations
```

`price_type` מבחין בין מחירון רשמי, מחיר מבוקש, עסקה שבוצעה ואומדן. אם אין מחיר אמין, המודול אינו מופיע.

## 5. חמש שפות אינן checkbox

שפה נחשבת מוכנה רק כאשר גם הפתיחה, היחידות, הכפתורים, ה־viewer, הטפסים, ההסכמות והליד תומכים בה. עמוד עם H1 מתורגם ושאר המוצר בעברית אינו עמוד רב־לשוני מלא.

# נוסח הדיסקליימר שהוטמע במפרט

הסדר הנכון הוא:

1. פתיחה ייחודית על הפרויקט.
2. המוצר והמידע של העמוד.
3. התוכן המרכזי.
4. פסקת ערך כללית על הפורטל.
5. הסתייגות משפטית גלויה וקצרה.

הנוסח המומלץ:

> **נדל״ן הוא פורטל עצמאי לבחירה ולקבלת החלטות בנדל״ן, המרכז במקום אחד מידע על פרויקטים, דירות, תוכניות, סביבת המגורים וכלי צפייה והשוואה. בעמודים שבהם זמינה חוויה אינטראקטיבית ניתן לבחון את הבניין, להשוות בין יחידות ולבקש פרטים בהתאם לבחירה שבוצעה.**

ואחריו:

> האתר אינו האתר הרשמי של היזם, הקבלן, המשווק או רשות ציבורית, אלא אם צוין במפורש אחרת. המידע עשוי להשתנות ואינו תחליף לבדיקה משפטית, תכנונית, שמאית, הנדסית או מסחרית מול הגורמים המוסמכים.

רק הפסקה המשפטית עטופה ב־`data-nosnippet`. היא אינה מוסתרת. הפסקה החיובית נשארת זמינה כמקור אפשרי לקטע החיפוש.

# אנשי המקצוע

ההמלצה אינה למחוק את המאגר ואינה להחיל כרגע תיאור מטא על 2,727 פרופילים.

במקום זאת:

- רשומת בסיס עם מידע ציבורי ומקור;
- פרופיל שנתבע ואומת;
- פרופיל מועשר;
- דמו או seed שאינו מתחזה לאדם אמיתי.

אזור “זה הכרטיס שלכם?” נשאר, אבל עובר מתחת לפתיחה העובדתית ונעטף ב־`data-nosnippet`.

הדירוגים המפוברקים יוצאים הן מהמסך והן מה־JSON-LD. אפשר להציג אותך כעורך דין אמיתי וכעורך הפורטל, ללא ביקורות מומצאות ובלי ליצור רושם שכל תוכן באתר הוא ייעוץ משפטי אישי.

# עמודי preview

`duo-preview` ועמודי preview כפולים אינם נשארים באוויר רק משום שהם noindex.

התהליך שנקבע:

1. גיבוי מלא.
2. בדיקת קישורים, sitemap, שימוש פנימי ונתוני חיפוש.
3. בירור אם העמוד עדיין נדרש לפגישות או ל־QA.
4. עמוד נטוש ללא יורש: הסרה ו־404/410.
5. עמוד עם יורש אמיתי: מיזוג והפניה קבועה.
6. סביבת QA פעילה: הרשאה, מחוץ למפה ו־noindex.

לא אימצתי את מדיניות “לעולם לא 301”, משום שהיא עלולה לפגוע גם במשתמש וגם במבנה האתר כאשר יש עמוד יורש אמיתי.

# ה־Quality Gate שנבנה

התוסף כולל **222 בדיקות ב־12 שערים**:

- אמת, ישות ומקורות;
- HTML מקור ואינדוקס;
- Hero ופולד ראשון;
- תוכן והוכחות;
- יחידות, מחירים, תוכניות ומלאי;
- נאמנות ואופטימיזציה של מודל;
- אינטראקציה, מובייל ונגישות;
- תוכנית, נוף, פנים, סטודיו והצעת מחיר;
- סביבה, מפות ומידע ציבורי;
- לידים, פרטיות ו־CRM;
- ביצועים ואמינות;
- שפות, schema וממשל תוכן.

עמוד ירוק רק כאשר:

```text
ציון 90 ומעלה
+ אין כשל קריטי
+ יש evidence לבדיקות הקריטיות
+ Unknown אינו Pass
+ N/A כולל נימוק
```

התוסף אינו משנה תוכן ציבורי. הוא שומר רק ציוני ביקורת, evidence, reviewer ותאריך.

**אין להתקין ישירות ב־production.** מתחילים ב־staging, ממפים את ה־post type והשדות בפועל, בודקים שני עמודי pilot, ורק אחר כך עוברים ל־12 עמודי התלת־ממד.

# מה לבצע לפני הפגישה עם מנכ״ל אקו סיטי

| סדר | פעולה |
|---:|---|
| 1 | להסיר דירוגי seed מה־UI ומה־schema |
| 2 | לשנות את עמוד אקו סיטי כך שיוצג כהדגמה עצמאית או הצעת פיילוט |
| 3 | לתקן את דף הבית: מסר אחד, חיפוש אחד ומשפך אחד |
| 4 | לבחור שני פרויקטים בלבד להדגמה מושלמת |
| 5 | לוודא שבמובייל הבניין אינו מוסתר או מתכווץ |
| 6 | לבצע ליד אמיתי מקצה לקצה ולשמור CRM receipt |
| 7 | להטמיע את הפתיחה והדיסקליימר החדשים בפיילוט |
| 8 | להסיר preview נטוש לאחר גיבוי ובדיקת יורש |

לא לבצע לפני הפגישה:

- מחיקה המונית;
- החלפת slugs;
- תיאורי מטא גורפים;
- מיזוג מאות עמודים;
- כתיבת 5,000 מילים אוטומטית לכל פרויקט;
- תרגום גורף;
- הפעלת importer נוסף לפני שהוא אידמפוטנטי.

המסר לפגישה צריך להיות:

> **NadLan אינו מבקש להחליף את אתר אקו סיטי. הוא מוסיף שכבת גילוי ובחירה מדידה שמחברת חיפוש, מידע, תלת־ממד, יחידה ונציג מכירות. מתחילים בשני פרויקטים, מגדירים מקור אמת ו־SLA, ומודדים אם נוצרות יותר פגישות איכותיות.**

כל חומרי הפגישה, התסריט ותכנית ששת הימים נמצאים בתוך תיקיית `07-ECO-CITY-MEETING` בחבילת־העל.
