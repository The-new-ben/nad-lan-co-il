# 00-EXPECTATIONS — התקן הפנימי של nad-lan.co.il (מול זה שופטים, לא מול "העולם")

זה מסמך המצופה. כשל = פער בין מה שיש בקובץ לבין מה שכתוב כאן. מה שמסומן
"by-design" אינו כשל לעולם, גם אם מוזר בעיניך.

## 1. זיהוי סוג הדף (לפי ה-URL ב-manifest.csv)

| תבנית URL | סוג | מה מצופה במיוחד |
|---|---|---|
| `/` וכן `/en/ /fr/ /ru/ /ar/` | בית (5 שפות) | מגה-תפריט, שער נכסים, canonical עצמי + אשכול hreflang מלא |
| `/projects/<slug>/` | עמוד פרויקט | ראו סעיף 3 — הסטנדרט המחמיר ביותר |
| `/projects/` | קטלוג | כרטיסי פרויקטים, בלי כתובות `?city=` |
| `/tours/`, `/tour/...` | סיורים | כרטיסי סיור, קישורים חיים לקבצי הסיור |
| `/echo-city/` | דף מתחם מיוחד | head מינימלי by-design (מוגש כעמוד עצמאי); טופס ליד |
| מחשבון/מדריך (mortgage, tax, glossary...) | כלי/מאמר | h1 יחיד, תוכן ממשי, בלי טקסט פילר |
| דירות למכירה/להשכרה | listings | כרטיסים אמיתיים; רצועת סיורים |
| `-en/ -fr/ -ru/ -ar` בסוף סלאג או `/en/...` | אחות-שפה | `lang`/`dir` נכונים, בלי עברית דולפת לממשק |

## 2. בדיקות אוניברסליות (כל דף, כל שורה)

**Head:**
- `<title>` אחד, 10–70 תווים, ייחודי בכל האתר, מסתיים ב-"| נדלן" (או "· נדלן").
- meta description עד 165 תווים, ייחודית, מוכרת (לא תיאור גנרי).
- **canonical בדיוק אחד**, https, מצביע-על-עצמו (self). שניים = כשל גבוה.
- robots בלי noindex/nofollow לא-מכוון (עמוד ציבורי עם noindex = חוסם).
- og:title/og:description/og:image/og:url קיימים ועקביים עם title/canonical.
- hreflang: אם קיים — דו-כיווני ועקבי (כל שפה מפנה לכל השפות + x-default).
- charset + viewport קיימים; favicon קיים.

**מבנה:**
- **בדיוק h1 אחד.** אפס או שניים = כשל גבוה.
- היררכיית כותרות בלי דילוגים (h2→h4), בלי כותרות ריקות.
- אין `id` כפול; אין `href=""`/`href="#"` יתום/`javascript:void`.
- `lang` ו-`dir` תואמים לשפת הדף (עברית = rtl).

**סכמה (JSON-LD):**
- כל בלוק parseable. **FAQPage לכל היותר אחד; BreadcrumbList לכל היותר אחד.**
- תוכן הסכמה לא סותר את הטקסט הגלוי (מחיר בסכמה ≠ מחיר על הדף = חוסם).
- FAQPage רק אם השאלות באמת מופיעות גלויות על הדף.

**שפה וטקסט גלוי:**
- **אפס מקפים ארוכים** (— או –) בטקסט גלוי. מפריד תקני: "·" או "-".
- ביטויים אסורים (כל הופעה = חוסם): "בהמתנה לחומרי היזם", "יחליף אותו עם
  קבלתו", "בבדיקה מול היזם", "יוצגו עם קבלת נתונים", "תוכנית תתווסף",
  "טרם התקבלו", "מחכים ליזם", "אין שרטוטים", "0 חדרים", "כיוון בבדיקה",
  "· בקרוב".
- מילים פנימיות שאסור שיופיעו ב-source בכלל (גם בהערות): Codex, Lovable,
  lorem, TODO, FIXME, placeholder, xxx, לורם.
- אנגלית שדולפת לממשק עברי (כפתור/תווית באנגלית בדף עברית) = כשל בינוני.
- שגיאות עברית בוטות, משפטים קטועים, כפל רווחים נראה.

**יושרה (החוק החשוב ביותר):** נתון לא ידוע = מושמט, לעולם לא מוצהר. כל
"0" חשוד בשדה מספרי, תאריך עבר שמוצג כעתידי, מחיר/כמות שנראים מומצאים,
טענת-על בלי עיגון ("הפרויקט המבוקש בישראל") — לסמן.

**מדיה:**
- לכל `<img>` תוכן: alt בעברית ומשמעותי (לא ריק, לא שם קובץ). הדמיה חייבת
  "הדמיה להמחשה" בסביבה שלה או ב-alt.
- width/height או aspect-ratio (מניעת CLS) — היעדר גורף = כשל בינוני.
- **אסור בשום מקום**: קבצים בשם `ecocity-render*` (רנדרים ללא זכויות).
- src כפול/שבור, srcset לא עקבי.

**אבטחה ופרטיות:**
- טוקן שמתחיל `sk.` / מפתח API סודי / סיסמה = **חוסם מיידי**.
- אימייל פרטי חשוף שאינו של האתר; טלפון בפורמט שבור (מצופה 972... בקישורי
  wa/tel).

**URL (חוק הברזל):** מילה לא מופיעה פעמיים באותו נתיב
(`/mortgage-calculator/reverse-mortgage/` = כשל).

## 3. עמוד פרויקט — המצופה המלא

1. h1 יחיד = שם המותג (לא ניסוח קטגוריה כמו "פרויקט חדש בתל אביב").
2. פתיח מאמר עברי חזק בראש; **פס "אתר עצמאי" (aside.nl-projnotice) יושב
   בפתח המאמר — זה מיקומו הנכון (by-design), אבל חייב להופיע בדיוק פעם אחת**
   ולכלול "אינו האתר הרשמי של {היזם} ואינו מופעל מטעמו".
3. `NADLAN_SHOWROOM` (JSON גדול inline) קיים = by-design. היעדרו בעמוד
   פרויקט = כשל.
4. CTA (וואטסאפ/טופס) בטווח שני מסכי גלילה מהפתיח.
5. אסור: יחידות עם נתונים ריקים מוצגים, מחירים זהים חשודים לכל היחידות,
   כיווני אוויר מומצאים, מתקנים שלא הוזכרו במקור.
6. breadcrumbs גלויים + BreadcrumbList יחיד תואם.

## 4. by-design — לזהות ולא לדווח ככשל

- טוקן Mapbox שמתחיל `pk.` — טוקן **ציבורי** בכוונה (רק `sk.` אסור).
- ה-JSON הענק inline של NADLAN_SHOWROOM ומספר scripts גבוה בעמודי מנוע.
- הפס "אתר עצמאי" בפתח המאמר (המיקום מכוון; רק כפילות שלו = כשל).
- ‏/echo-city/ עם head מינימלי יחסית ושני scripts בלבד.
- מחרוזות `nl-`/`nlpjx-`/`nldc-` וכד' — מרחבי שמות פנימיים לגיטימיים.
- עברית RTL עם מספרים/מותגים LTR משובצים.
- הערות מפתח דוגמת "owner order", מספרי גרסה בהערות CSS.

## 5. דירוג חומרה

- **חוסם**: יושרה/משפטי/שבור — ביטוי אסור, נתון מומצא, סוד `sk.`, noindex
  על עמוד ציבורי, סכמה סותרת-גלוי, היעדר גילוי "אינו האתר הרשמי".
- **גבוה**: canonical≠1, h1≠1, כפל FAQPage/BreadcrumbList, title כפול בין
  דפים, hreflang שבור, קישור פנימי ל-404 מוכר.
- **בינוני**: מקפים, אנגלית דולפת, alt חסר, CLS, היררכיית כותרות, כפל id.
- **נמוך**: ליטושים, ניסוח, עקביות זנב title.

## 6. בדיקות רוחב (על כל הקבצים יחד, לא פר-דף)

- titles/descriptions כפולים בין דפים (קניבליזציה).
- שני דפים שנלחמים על אותה מילת-ראש בסלאג.
- דפוס כשל שחוזר בתבנית (אם אותו פגם ב-30 דפים — לדווח פעם אחת כ"מערכתי"
  עם רשימת הדפים, לא 30 פעם).
- עקביות זנב המותג בכל ה-titles.
