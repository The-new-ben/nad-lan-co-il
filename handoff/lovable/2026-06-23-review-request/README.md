## Apartment selection — corrected assessment

An earlier version of this brief claimed buyers could not select an apartment
because `.nlp3d-mv-hotspot` carries `display:none!important`. **That claim was wrong
and has been removed.** The facts:

- `.nlp3d-mv-hotspot` is a legacy model-viewer hotspot layer. It is hidden on
  purpose. It was replaced.
- The live selectable markers are `.nlp3d-stage-pick`, generated by JavaScript at
  runtime, visible, and wired to `selectUnit`. Selection of the authored units
  works.
- The 1.69.32 live QA (`docs/qa/screenshots/showroom-live-selection-16932-2026-06-24/`)
  is genuine: the before/after PNGs are distinct captures (verified by SHA256), and
  the camera moves to the selected unit.

## The real limitation (this is what to weigh, not a bug)

Selection resolves to **authored apartment targets** plus a nearest-unit fallback
for raw taps on the bare model surface. It is **not** true per-window picking on the
3D mesh. The current Rainbow GLB exposes no apartment-level mesh IDs or official BIM
geometry. Exact click-any-window selection requires official apartment geometry
(BIM/IFC) or a GLB exported with per-unit pickable meshes. This is owner-input, not
a code fix.
