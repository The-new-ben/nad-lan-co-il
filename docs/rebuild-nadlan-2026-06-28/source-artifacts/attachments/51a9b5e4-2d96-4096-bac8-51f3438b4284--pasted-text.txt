BLOCKER #1 (root cause, already diagnosed — fix this first)
The live model-viewer script renders as a classic script with no type="module":

<script id="nadlan-model-viewer-js" src=".../model-viewer/4.3.1/model-viewer.min.js?ver=4.3.1">
model-viewer 4.3.1 is an ES module. Loaded as a classic script the browser throws "Unexpected token 'export'", the custom element never registers (customElements.get('model-viewer') is undefined), so <model-viewer> stays blank. wp_script_add_data($handle,'type','module') does nothing — WP core has no handler that turns it into a tag attribute.

Fix (verified WP 6.x best practice — script_loader_tag filter):

// in inc/project-3d.php, near the model-viewer enqueue:
add_filter( 'script_loader_tag', function ( $tag, $handle, $src ) {
    if ( 'nadlan-model-viewer' === $handle ) {
        return '<script type="module" src="' . esc_url( $src ) . '" id="nadlan-model-viewer-js"></script>' . "\n";
    }
    return $tag;
}, 10, 3 );
Keep the wp_register_script(...'nadlan-model-viewer'...) enqueue; the filter is what actually adds type="module". The wp_script_add_data(...,'type','module') line can stay or go — it's inert.

Prove the fix in Chrome console (must be true before you claim success):

const mv = document.querySelector('model-viewer');
mv.addEventListener('load', () => console.log('GLB loaded?', mv.loaded)); // → true
