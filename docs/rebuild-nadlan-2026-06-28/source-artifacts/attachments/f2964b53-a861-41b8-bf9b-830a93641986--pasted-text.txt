1) Direction: you're right — cells, not dots
Your instinct matches how real selectors work: the building itself is the control. DIGBY highlights active apartment areas in perspective on the 3D render; Render Vision opens floor/area/orientation/availability when you click the apartment on the facade; Zillow/Engrain stress exact unit location + view. Floating decorative dots fail the buyer's task ("which apartment, where, is it available, what's the view"). Keep the apartment-cell direction. Don't defend dots.

2) The keystone you must not skip: data-driven cell geometry
The reason clicks feel disconnected is in stagePickOffset() (~line 1575):

function stagePickOffset(u){
  if(id.indexOf('boutique')>-1){return -245}   // magic px, eyeballed for ONE render
  if(id.indexOf('sw')>-1){return -128} ...
}
This is hardcoded to Rainbow's unit IDs. Any unit whose id lacks those substrings collapses to left:50% — cells stack in a column that isn't on the apartments. Fix the model, not the magic numbers:

Author per-unit position in the CMS. Add stage_x (0–100, % across the tower footprint) to the unit contract. top is already correct (floor-normalized — keep it).
Consume it in renderStagePicks():
function cellX(u, idxInFloor, countInFloor){
  if(u.stage_x!=null && u.stage_x!=='') return clamp(+u.stage_x,2,98)+'%';
  // auto-spread units that share a floor, evenly across footprint — works with ZERO authoring:
  if(countInFloor>1){var step=Math.min(26,64/countInFloor);
    return 'calc(50% + '+((idxInFloor-(countInFloor-1)/2)*step)+'px)';}
  return 'calc(50% + '+stagePickOffset(u)+'px)';   // legacy fallback, last resort
}
PHP contract (nadlan_p3d_clean_unit_items(), ~line 170): add
'stage_x' => isset($u['stage_x']) && $u['stage_x']!=='' ? max(0,min(100,(float)$u['stage_x'])) : '',

3) The 1.65.5 patch list (your four findings — confirmed real, with the fix)
(a) Mobile tap target — your 42px cells fail WCAG 44px. In the @media(max-width:760px) block, the cell hit area (not just the visual) must be ≥44px. Make the interactive element 48px and let the visual rectangle be smaller inside it:

.nlp3d-stage-pick{min-width:48px;min-height:48px}      /* hit area */
.nlp3d-stage-pick .nlp3d-cell{ /* visual rect can be 78×42 inside the 48px touch box */ }
Don't shrink the button to the rectangle — keep the button ≥48px and center the smaller visual in it.

(b) Right-crop from the legacy nudge. fitMobileShowroom() sets --nlp3d-mobile-nudge + is-mobile-edge-fixed (translateX). That hack existed to fight the OLD constrained-width layout. Now that 1.65.4 made the block alignfull + width:calc(100vw - …) centered, the nudge double-applies → crop. Neutralize it:

// in fitMobileShowroom(): the block is already full-bleed+centered via alignfull; stop nudging
root.style.setProperty('--nlp3d-mobile-nudge','0px');
root.classList.remove('is-mobile-edge-fixed');
If nothing else reads the nudge, delete the function body and its callers. Verify on a 390px viewport that left and right gutters are equal.

(c) Selected-card falling below the fold on mobile. A bottom-sheet that lives at the end of a tall scroll column ends up off-screen (your QA proved it). On mobile, pin it to the stage instead of appending far below:

@media(max-width:760px){

}
and on selection call stageCard.scrollIntoView({block:'nearest',behavior:'smooth'}) inside renderStageCard() when hasStageSelection flips true. Goal: select a cell → its card is visible without scrolling.

(d) Buyer-facing funnel wording. Any visible "לידים / פאנל / CRM / lead / funnel" string in buyer DOM is a trust leak. Rename to buyer language — "בקשת פרטים", "פנייה ליזם", "שמירת דירה". Keep funnel/CRM terms in admin + track() event names only (those aren't rendered).

4) The reliability bug you probably haven't spotted (include it)
There's a tap-vs-drag double handler. dragExcludedTarget() (~2343) explicitly returns false for .nlp3d-stage-pick, so the scene starts a drag even when the pointer lands on a cell, then endDragAt() calls selectUnit(...,'stage-pick-tap') and the cell's own click fires activateStagePick. Two effects: double selectUnit/double tracking, and on browsers where scene.setPointerCapture() swallows the synthetic click, the cell's click never fires — only the tap path does, intermittently. Fix: exclude cells from scene-drag so their click always owns the interaction:

function dragExcludedTarget(target){
  if(target&&target.closest&&target.closest('.nlp3d-stage-pick')) return true; // was: return false
  ...
}
Then drop the tappedUnit selectUnit branch in endDragAt() (cells handle themselves; the tower body still drags). Net: one click = one selection, every time.
