The midterm goal (achievable, ~v1.64.x in slices)
Turn the Rainbow block from a 3D demo into a buyer apartment-selector product: picking an apartment is the default and the hero. Every unit is obviously clickable on the building (label + status color + pulse on recommended + hover info), the selected apartment shows a dominant action card (details / view-from-apartment / contact-the-developer), a short SEO intro sits above the block, click targets are comfortable on desktop AND mobile, and every piece (units, price, status, labels, video, contact) is CMS-editable so a contractor can run their own project. Mobile = guided vertical flow: intro → compact model → selected apartment → CTA.

The niche intelligence (build for these intents — researched)
Buyer journey when choosing an off-plan apartment online (in priority order):

"Which units are available?" → availability must be visible first (color-coded).
"What's the price / payment plan?" → off-plan sells on below-market + staged payments; show estimate + "אומדן לא מחייב".
"What does it look like — floor plan, the view from this apartment, finishes?"
"Which floor / rooms / size fits me?" → filter, and highlight matches on the building.
"Is this a good unit?" → comparison + "פופולרי / נוף לים" recommended tags.
"How do I reserve / talk to someone?" → lead/contact with the unit attached.
Contractor/developer journey — why they PAY (this is the monetization):

Show inventory beautifully + update availability/price themselves (CMS, no developer needed).
Capture qualified leads with unit context piped to their funnel/WhatsApp.
See which units get interest (analytics).
Look premium vs competitors; offload the sales centre (self-serve).
Monetization model to design toward: per-project monthly subscription + setup fee, lead/reservation fees later, upsell real BIM/video/AR. (Proptech comps run ~$19–129/project/month.)

Slice 3 — Selected-apartment action card as the hero. When a unit is picked, a dominant card docks near the model (top-left on desktop, sticky panel on mobile): big title ("דירה 31 · 5 חד׳ · קומה 12"), status chip, view, price-estimate (non-binding), and 3 clear actions: פרטים מלאים · מבט מהדירה · דברו עם היזם. This is the buyer's "I picked this, here's what's next" moment.

Slice 4 — CMS editability (the monetization enabler). Slice 5 — Progressive disclosure. Hide advanced controls (sun/directions, environment, Mapbox "view from apartment") behind tabs that appear AFTER an apartment is selected. Rename controls plainly: "סובב מודל · מבט מהדירה · שמש וכיוונים · סביבה." Don't show every tool at once (NN/g progressive disclosure).

Slice 6 — Contractor communication + lead. From the selected-apartment card, "דברו עם היזם" opens the lead/WhatsApp flow with the unit attached (unit id, floor, rooms, price-estimate) into the existing /nadlan/v1/lead funnel. The contractor's contact/WhatsApp is a CMS field per project.
