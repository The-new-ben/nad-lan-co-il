# הארכיטקטורה המומלצת: Selected-unit scene

## החלטה

הדירה הנבחרת אינה עוד “פאנל עשיר”. היא מצב מלא ומפורש של התיאטרון.

השם המוצע במנוע: `selected-unit scene` או `unit surface`.

```text
EXPLORE_BUILDING
      │ select(unitId, source)
      ▼
VIEW_SELECTED_UNIT
      │ openTool(plan | view | tour | studio)
      ▼
VIEW_UNIT_TOOL
      │ closeTool()
      ▼
VIEW_SELECTED_UNIT
      │ backToBuilding()
      ▼
EXPLORE_BUILDING
```

המודל נשאר mounted בכל המעברים. הוא אינו מוחלף בתמונה ואינו מאותחל מחדש.

## מדוע זו ההמלצה

המצב הנוכחי נולד מהנחה שכל פונקציה של הדירה חייבת לחיות בתוך `nl-panel`. ההנחה אינה מחזיקה במובייל: מעטפת בגובה חלקי אינה יכולה להכיל תוכן שאורכו פי שלושה עד חמישה ממנה בלי nested scroll.

ההמלצה משנה את יחידת הארכיטקטורה:

- לא “panel ובתוכו tabs”.
- כן “state של דירה ובתוכו כניסות לכלים”.

כך מקיימים בו־זמנית את הדרישות:

- אין מסגרת בתוך מסגרת.
- אין גלילה פנימית.
- האלומה נראית ללא חיפוש.
- המשתמש רואה מסך בחירה שלם.
- הכלים מקבלים שטח מלא.
- המודל התלת־ממדי נשאר הדגל.
- הדסקטופ אינו נשבר.

## עקרונות שאינם נתונים למשא ומתן

1. **בעלות יחידה על state:** `engine.js` הוא הבעלים היחיד של בחירה, כלי פתוח ומצב חזרה.
2. **בעלות יחידה על DOM:** אין PHP patch שמסדר מחדש DOM לאחר `render()`.
3. **אין MutationObserver לצורך UI:** המנוע כבר יודע מתי יחידה נבחרה; אין צורך לצפות בעצמו.
4. **כלי fullscreen מחובר ישירות ל־`document.body`:** לא לצאצא של theater, panel או אב בעל `transform`.
5. **אין קריאת מידע מתוך טקסט מתורגם:** כיוון נלקח מ־`u.dir`; קומה מ־`u.floor`; geo מ־`project().geo`.
6. **fallback ישר:** בלי geo מדויק מוצגת אלומה סכמטית, לא מפה שמתיימרת להיות מדויקת.
7. **כל מעבר הפיך:** סגירת כלי מחזירה לאותה דירה; חזרה לבניין מחזירה לאותו hotspot.
8. **טלפון הבעלים הוא שער קבלה:** אמולטור אינו אישור production.

## מודל state

ה־state המינימלי:

```js
var state = {
  unitId: null,
  tool: null,
  tab: "plan",       // נשאר זמנית לתאימות לאחור
  favs: [],
  compare: []
};

var unitSurface = {
  selectionSource: null,
  returnFocus: null,
  beamMap: null,
  toolCleanup: null
};
```

משמעות השדות:

| שדה | מקור אמת | שימוש |
|---|---|---|
| `state.unitId` | מזהה היחידה מתוך payload | הדירה המוצגת, deep link, form context |
| `state.tool` | `null`, ‏`plan`, ‏`view`, ‏`tour`, ‏`studio` | קובע אם ואיזה כלי פתוח |
| `selectionSource` | האלמנט שממנו נבחרה הדירה | החזרת focus והחלטה אם לגלול לתיאטרון |
| `beamMap` | מופע Mapbox יחיד | teardown בעת מעבר דירה/סגירה |
| `toolCleanup` | פונקציית cleanup | סילוק listeners, מפה או iframe state |

אין class על DOM שמשמש מקור אמת. classes הם פלט של state בלבד.

## חוזה הנתונים של יחידה

ה־renderer המשותף צריך לקבל אובייקט מנורמל:

```js
{
  id: "R-1204",
  label: "דירה 1204",
  floor: 12,
  rooms: 4,
  sqm: 118,
  balcony: 14,
  dir: "SW",
  status: "available",
  plan: "https://.../plan.jpg",
  tour_url: "https://...",
  project_id: "rainbow-tel-aviv"
}
```

`dir` חייב להיות enum יציב כגון `N`, ‏`NE`, ‏`E`, ‏`SE`, ‏`S`, ‏`SW`, ‏`W`, ‏`NW`. שמות “ים”, “עיר” או “פארק” הם שכבת תוכן נפרדת ואינם תחליף ל־bearing.

Utopia תוכל להשתמש באותו renderer רק אחרי שהיא ממירה את הנתונים שלה לחוזה הזה.

## מבנה המסך במובייל

ה־theater הנבחר מקבל גובה viewport דינמי:

```text
┌───────────────────────────────────┐
│  מודל חי, יחידה מסומנת  12–18dvh │
├───────────────────────────────────┤
│  חזרה לבניין  דירה 1204  זמינות │
├───────────────────────────────────┤
│                                   │
│  מפה + אלומת כיוון, תמיד גלויות  │
│                                   │
├───────────────────────────────────┤
│  קומה │ חדרים │ מ״ר │ מרפסת      │
├───────────────────────────────────┤
│  איך הדירה מחולקת?                │
│  החלון פונה לים — הביטו החוצה     │
│  רוצים להרגיש את החלל?            │
│  איך היא תיראה שלכם?              │
├───────────────────────────────────┤
│ שמירה │ השוואה │ שיתוף │ WhatsApp │
├───────────────────────────────────┤
│         בנו הצעה לדירה            │
└───────────────────────────────────┘
```

זה אינו scroll container. על מסך נמוך במיוחד הדלתות עוברות מ־1×4 ל־2×2; הן אינן נעלמות ואינן הופכות לקרוסלה.

### המודל בכל רגע

| מצב | התנהגות המודל |
|---|---|
| חקירת בניין | גודל מלא; סיבוב ובחירת hotspots |
| דירה נבחרת | אותו model-viewer באותו DOM, ברצועה קומפקטית; היחידה נשארת מסומנת |
| כלי פתוח | נשאר mounted מאחורי dialog; auto-rotate מושהה אם פעיל |
| סגירת כלי | אותה מצלמה, target ויחידה; אין re-fetch ל־GLB |
| חזרה לבניין | השטח חוזר לגודל מלא וה־hotspot נשאר מקור focus |

## מה קורה בלחיצה על דירה

### בחירה מתוך המודל

1. קוראים את geometry הדרוש לפני כתיבת DOM, כדי למנוע forced reflow.
2. שומרים `selectionSource`.
3. מעדכנים `state.unitId` ו־deep link.
4. מסובבים/מכוונים את המצלמה אל היחידה.
5. מרנדרים את סצנת הדירה.
6. מעבירים focus ל“חזרה לבניין” בלי להזיז scroll.

### בחירה מתוך כרטיס מלאי בהמשך העמוד

אותם צעדים, ובנוסף:

```js
theater.scrollIntoView({
  block: "start",
  behavior: prefersReducedMotion ? "auto" : "smooth"
});
```

הגלילה היא גלילת המסמך היחידה. זו אינה תוספת קוסמטית: בייצור הנוכחי הבחירה נעשית כשהתיאטרון עשוי להיות יותר מ־1,400px מעל ה־viewport.

## סצנת מפה ואלומה

### שכבות

```text
Mapbox non-interactive, אם יש מיקום מדויק
        +
SVG beam מחושב מתוך bearing
        +
נקודת פרויקט/דירה מרכזית
        +
כיתוב: “החלון פונה אל הים”
```

ה־SVG הוא מקור התצוגה של הכיוון. Mapbox הוא enhancement של ההקשר, לא מקור החישוב.

### bearing

```js
var DIR_BEARING = {
  N: 0, NE: 45, E: 90, SE: 135,
  S: 180, SW: 225, W: 270, NW: 315
};
```

אין לנתח מילים כמו “דרום־מערב” מתוך `.nl-muted`. הטקסט משתנה בין חמש שפות, בעוד enum אינו משתנה.

### אמת גאוגרפית

| מצב נתונים | תצוגה |
|---|---|
| lat/lng מדויקים + Mapbox זמין | מפה שקטה, non-interactive, עם אלומה |
| lat/lng ברמת עיר בלבד | רקע סכמטי + אלומה + הודעת דיוק |
| Mapbox חסום או נכשל | אותו fallback סכמטי; מסך הדירה נשאר שימושי |
| כיוון חסר | אין להמציא bearing; מוצגת הודעה שהכיוון טרם אומת |

## פתיחת כלים

כל הכלים משתמשים באותו shell:

```html
<dialog id="nl-unit-tool">
  <header>
    <button>חזרה לדירה</button>
    <h2>תוכנית הדירה</h2>
  </header>
  <div class="nl-unit-tool__body">
    <!-- canvas יחיד -->
  </div>
</dialog>
```

ה־dialog נוצר פעם אחת ומצורף ישירות ל־`document.body`.

### תוכנית

- `img` עם `object-fit:contain` בתוך canvas מלא.
- אין scroll פנימי.
- אם בעתיד נדרש zoom, הוא צריך להיות transform של התמונה, לא scrollable div.

### נוף מהחלון

- מופע Mapbox אחד.
- `PointerEvent` עם `setPointerCapture`.
- listeners מחוברים ל־host ומסולקים באמצעות `AbortController`.
- אין `mousemove` או `mouseup` קבועים על `window`.
- אין טעינה דינמית נוספת של Mapbox; WordPress הוא בעל ה־enqueue.

### סיור

- iframe בגובה המשטח.
- אם ספק הסיור אינו תומך embed, קישור גלוי לפתיחה חיצונית.
- כותרת וחזרה נשארות בבעלות NadLan.

### מעצב

בשלב הראשון נשמר מנגנון המעצב הקיים משום שהוא כבר body-level ומרגיש נכון לבעלים. הוא מקבל adapter לאותו state ולכפתור “חזרה לדירה”. רק לאחר אישור המסלול המרכזי מאחדים את shell שלו.

## History, Back ו־focus

פתיחת כלי מוסיפה marker ל־`history.state`. לחיצה על Back במכשיר סוגרת את הכלי ולא מוציאה מן הפרויקט. סגירה בכפתור או Escape מחזירה focus לדלת שפתחה את הכלי.

סדר החזרה:

```text
כלי → דירה → בניין → היסטוריית העמוד הקודמת
```

אין לקרוא `history.back()` ללא marker שהמנוע עצמו יצר; אחרת משתמש שנכנס ישירות ליחידה עלול לעזוב את האתר.

## דסקטופ

### שלב ראשון

production נשאר ללא שינוי. הארכיטקטורה החדשה מאחורי flag של mobile sandbox בלבד.

### היעד לאחר אישור מובייל

- פאנל הצד נשאר ברוחב ובמיקום המוכרים.
- תוכנו מוחלף ב־summary קומפקטי: אלומה, facts, דלתות 2×2 ופעולות.
- אין `overflow-y:auto`.
- הכלים נפתחים באותו body-level dialog.
- המודל נשאר בגודלו ובמיקומו הנוכחיים.

כך נשמרת הצלחת הדסקטופ בלי לשמר שתי ארכיטקטורות UI שונות.

## בעלות קוד מוצעת

| אחריות | קובץ בעלים | מה לא לעשות |
|---|---|---|
| state, renderer, dialog lifecycle | `engine.js` | לא להזריק JS מקביל מתוך PHP |
| CSS רכיבי המנוע | inline style המחובר ל־handle של showroom CSS | לא להשתמש בשמות גלובליים כמו `.nl-tabs` |
| נתוני פרויקט ויחידה | `showroom-engine.php` | לא לגרד נתונים מ־DOM מתורגם |
| מחרוזות | `i18n.js` | לא לשכפל EN ל־FR/RU/AR ללא תרגום |
| enqueue וגרסאות | WordPress/PHP | לא לטעון Mapbox פעם שנייה ב־JS |
| Utopia adapter | המודול של Utopia + contract משותף | לא להניח ש־`#nl-root` קיים שם |

## כללי CSS מונעי רגרסיה

1. namespace חדש: `.nl-unit-*`; אין שימוש ב־`.nl-tabs`.
2. `dialog` מקבל `top/right/bottom/left` מפורשים וגם `width/height`; אין `inset` shorthand.
3. `position:fixed` קיים רק בצאצא ישיר של `body`.
4. `overflow:hidden` או `clip` בתוך כלי; אין `auto`/`scroll`.
5. `100dvh` עם safe-area; אין הסתמכות בלעדית על `100vh`.
6. landscape מקבל layout דו־עמודי, לא כיווץ אנכי בלתי אפשרי.
7. `[hidden]` מקבל `display:none!important` בתוך namespace כדי למנוע דריסה בקסקדה.
8. touch targets הם לפחות 44×44px.

## שפות

ה־renderer משתמש באותם keys בכל השפות. RTL נקבע לפי שפה ולא לפי שם פרויקט.

חובה לבדוק:

- עברית וערבית: RTL מלא, לרבות חצים, סדר facts ו־focus.
- אנגלית, צרפתית ורוסית: LTR.
- צרפתית ורוסית עם טקסט ארוך ב־30%–50% מן האנגלית.
- אין כיוון פיזי שמתהפך בגלל RTL; bearing גאוגרפי אינו direction של ממשק.

## נגישות

- “חזרה לבניין” הוא כפתור אמיתי.
- `dialog.showModal()` יוצר top layer ומונע interaction עם הרקע.
- בעת fallback ללא `dialog`, root מקבל `inert` מפורש.
- Escape סוגר כלי; אינו סוגר קודם מצב אחר בטעות.
- focus חוזר למקור.
- יחידות polygon/SVG חייבות להיות keyboard reachable או לקבל חלופה מקבילה ברשימה.
- סטטוס יחידה ופעולות שמירה/השוואה משתמשים ב־`aria-pressed`/טקסט מתאים.

## ביצועים

- מודל אחד נשאר mounted; אין יצירה מחדש בין states.
- geometry reads קודמים ל־DOM writes.
- מופע beam map מוסר לפני רינדור יחידה אחרת.
- כלי הנוף טוען map רק בפתיחה ומסיר אותו בסגירה.
- אין observers או listeners שאין להם teardown.
- אין ספרייה חדשה.

## קריטריוני קבלה ארכיטקטוניים

מצב אינו מתקבל אם אחד מהבאים מתקיים:

- אלמנט בתוך `#nl-root` או `#nl-unit-tool` הוא scroller פנימי בפועל.
- בחירה מן המלאי אינה מביאה את סצנת הדירה ל־viewport.
- המפה או האלומה אינן נראות במסך הראשון.
- כלי נחתך בגלל אב עם `transform` או `overflow`.
- סגירת כלי מאבדת יחידה, מצלמה או focus.
- שפה זרה נופלת לאנגלית בלי סימון.
- Utopia מסומנת “מכוסה” בלי adapter עובד.
- production נפרס לפני מעבר בטלפון הבעלים.

# החלופה: route/מסמך ייעודי ליחידה

## מבנה

```text
/projects/rainbow-tel-aviv/?unit=R-1204
```

או URL קנוני נפרד ליחידה, שבו קיימים:

- hero של המודל והיחידה הנבחרת.
- אלומה ומפה.
- facts ופעולות.
- document scroll יחיד.
- אותם dialogs לכלים.

## יתרונות

- deep link ושיתוף חזקים.
- אפשרות ל־server rendering ו־SEO ליחידות אם קיים ערך עסקי לכך.
- בידוד מוחלט מהעמוד הארוך ומה־CSS ההיסטורי.
- browser history טבעי.

## חסרונות

- מעבר עלול לאתחל WebGL ו־GLB.
- תחושת הבחירה הישירה מתוך הבניין נחלשת.
- יש עלות navigation ושרת גבוהה יותר.
- נוצרת אחריות canonical/indexability לכל יחידה.

## מתי לבחור בחלופה

- אם גם לאחר בניית state מקורי בתוך המנוע לא ניתן לבודד את cascade ההיסטורי.
- אם שיתוף וקמפיינים ליחידה ספציפית הופכים לדרישה מרכזית.
- אם Utopia ומודולים עתידיים דורשים מסמך יחידה עצמאי ממילא.

זו חלופה תקפה, אך ההמלצה הראשית נשארת state פנימי: היא שומרת טוב יותר על התיאטרון התלת־ממדי כיתרון המבדל.
