# תקציר מנהלים

## פסק הדין

חוויית בחירת הדירה נשברת במובייל מסיבה ארכיטקטונית, לא בגלל מרווחים או כפתורים לא נכונים.

`engine.js` מכניס את כל תוכן הדירה — נתונים, tabs, תוכנית, נוף, סיור, שמירה, השוואה, WhatsApp, הצעה, brochure, designer ופנייה — לתוך `#nl-panel-body`. במובייל הפאנל הוא overlay מוחלט בגובה מרבי של 62% מהבמה, וה־body שלו מוגדר `overflow-y:auto`.

במדידה החיה:

- גובה חלון התוכן היה 291px.
- גובה התוכן היה 941–1,052px בטאב תוכנית.
- ב־Rainbow, לאחר פתיחת הנוף, גובה התוכן היה 1,468px.
- הפאנל כיסה 62% מהמודל.
- בבחירה מכרטיס מלאי, הפאנל יכול להיפתח כולו מחוץ ל־viewport משום ש־`selectUnit()` אינו מחזיר את המשתמש לתיאטרון.

לכן nested scroll אינו תקלה נקודתית אלא תוצאה מתמטית של המבנה.

## ההמלצה

להפוך בחירת דירה ל־state מקורי של התיאטרון:

```text
בניין תלת־ממדי
  → בחירת דירה
  → מסך דירה אחד: מודל חי + מפה ואלומה + נתונים + דלתות
  → כלי fullscreen ברמת body
  → חזרה לדירה בנגיעה אחת
```

במובייל המודל נשאר mounted בשורת־על קומפקטית. המפה והאלומה תמיד גלויות. הנתונים והדלתות נכנסים באותו viewport ללא גלילה פנימית. תוכנית, נוף וסיור נפתחים ב־`<dialog>` שמצורף ישירות ל־`document.body`. המעצב הקיים משמש reference ל־body-level overlay.

בדסקטופ שומרים בתחילה על פאנל הצד. רק לאחר אישור המובייל בארגז החול מחליפים את תוכנו ב־summary קומפקטי ללא scroll, עם אותם dialogs.

## למה לא עוד bottom sheet

ה־bottom sheet הקודם שמר את `.nl-panel__scroll { overflow-y:auto }`, ולכן רק שינה את גובה המסגרת. v2 היה נכון יותר חזותית, אבל הוזרק כטלאי PHP/DOM חיצוני למנוע. הוא פיצל state, השתמש ב־MutationObserver, כלא `position:fixed` תחת אב עם `transform`, ונלחם בקסקדה קיימת.

הפתרון החדש חייב להיות בבעלות `engine.js`, ללא MutationObserver וללא JS inline ב־PHP.

## חסמי שחרור

לא עוברים לייצור לפני שכל אחד מהבאים מתקיים בטלפון הפיזי של הבעלים:

- בחירה מ־hotspot ומכרטיס מלאי תמיד מציגה את מסך הדירה מיד.
- המודל, המפה/אלומה, הנתונים והדלתות גלויים במסך אחד.
- אין אף scroll container פנימי במצב דירה או בכלי.
- כל כלי נסגר בנגיעה אחת, Escape ו־Android Back.
- המצלמה והדירה הנבחרת נשמרות לאחר חזרה.
- HE/AR תקינות RTL ו־EN/FR/RU תקינות LTR.
- Utopia נבדקת כמנוע נפרד עד לאימוץ contract משותף.
- CSS, JS ו־PHP משוחררים כ־artifact אטומי בעל מספר גרסה אחד.

## סיכונים קריטיים נוספים

1. `onSubmit()` מדווח הצלחה גם כאשר שליחת הליד נכשלת (`.catch(done)`) ומאפס את הטופס.
2. קישורי `home.html` ו־`project.html?...` שהמנוע מייצר מחזירים 404 בעמודי WordPress.
3. FR/RU/AR הן ברובן clone של EN, ו־feature bar נשאר עברית/RTL בשפות זרות.
4. Mapbox ו־Leaflet עשויים להיטען יחד; listeners של תצוגת החלון מצטברים ללא teardown.
5. Utopia אינה משתמשת ב־`#nl-root` ולכן שינוי במנוע הראשי לא יגיע אליה אוטומטית.
