# כיכר המדינה — QA עצמאי ל־1.72.373, עם השלמה נפרדת ל־1.72.374

מאת: מאיה / Codex · HAD-375 · בדיקת 30.9.2026 · מיועד לקלוד המיישם.

## ההחלטה בקצרה

השינוי ב־373 פתר חלק חשוב מהתקלה: העמוד גולל מעל הבמה, פאנל הקומה נמצא בזרימת העמוד, והייעוץ נגיש בתוך המסך המלא. אלה שיפורים שנבדקו באתר החי, לא רק בקוד או בהחלפת קבצים מקומית.

עם זאת, 373 אינה סגירה מלאה של הבדיקה: החלקה אנכית גם סובבה את המצלמה; בעולם נשארו אייקונים ללא שמות ובחפיפה; ובמפת הסביבה שמות אינם נראים בזום הפתיחה. אין הצדקה לנורה ירוקה כוללת.

במהלך העבודה עלתה 374. הפרדתי את המדידות: ב־374 החלקה אנכית כבר אינה מסובבת את המצלמה בששת מקרי השפה/רוחב שבדקתי. אין להמשיך לדווח על התקלה הזאת כאילו היא עדיין משוחזרת באותה בדיקה. עדיין פתוחים שמות במפת הפתיחה, נגישות תוויות, הגדלת טקסט, וגלגלת דסקטופ אחרי לחיצה בבמה. ראו סעיף 7.

לא שיניתי מוצר, אתר, נתונים, tracking, Git או הגדרות דפדפן של בן. לא שלחתי ליד או WhatsApp. נכתב רק מסמך זה. אין כאן הוראת פריסה או rollback.

## 3. תוצאות 373 לפי חומרה והקוד האחראי

### P1 / M01 — העמוד זז, אבל גם המצלמה

במחווה אנכית של 200px, על canvas שאומת ב־elementFromPoint, העמוד נע 185px. אותה מחווה שינתה את quaternion המצלמה בכ־6.6–6.7 מעלות. הדבר חזר גם בהחלקה אלכסונית ובהחלקה אחרי יציאה ממסך מלא.

| מקרה | תנועת העמוד | שינוי זווית המצלמה |
|---|---:|---:|
| HE390 | 185px | 6.631° |
| HE320 | 185px | 6.715° |
| EN390 | 185px | 6.726° |
| EN320 | 185px | 6.699° |
| AR320 | 185px | 6.723° |

הזווית חושבה מ־`2*acos(abs(dot(qBefore,qAfter)))`, עם clamp ל־1; לא מהתרשמות מצילום. מרחק הגלילה לבדו היה מסתיר את התקלה.

ראיית קוד בגרסת 373: `world.js`, שורות 1052–1053 ו־2690–2718: אצבע אחת עדיין מחוברת ל־OrbitControls ROTATE, בלי סינון כוונת ציר לפני הפעלת הסיבוב. `pan-y` מאפשר לדפדפן ליטול את הגלילה, אך אינו מבטל בדיעבד תנועות מצלמה שנקלטו קודם. זהו הסבר סביר משילוב הקוד והמדידה, לא trace פנימי מלא של OrbitControls.

```js
controls.touches.ONE = THREE.TOUCH.ROTATE;
controls.touches.TWO = THREE.TOUCH.DOLLY_PAN;
// bindInput, 373
on(cv, 'pointerdown', (e) => {
  down = { /* pointer state */ };
  controls.enableZoom = true;
});
on(cv, 'pointercancel', () => { down = null; });
```

כיוון תיקון: לשמר את ההחלטה על סיבוב אופקי, אבל להפריד את בעלות המחווה לפני שהמצלמה מקבלת תנועה אנכית/אלכסונית. לבדוק גם damping אחרי cancel/up, לא רק את הפריים בעת הרמת האצבע. אין לשנות `touch-action` באמצע מחווה ולצפות שהדפדפן יחליף החלטה. הסעיף המקצועי הרלוונטי הוא [Pointer Events: touch-action](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property).

**עדכון 374:** תרחיש ההחלקה האנכית הזה כבר עבר ללא שינוי מצלמה. אין צורך לתקן שוב על סמך 373 בלבד; עדיין נדרשות אלכסוניות, חלון, רצף אצבע שנייה/ביטול ומכשירים פיזיים.

### P1 / M17 — אייקון אינו תחליף לשם, וחלקם חופפים

ב־HE390 נמדדו 13 אייקונים בעולם; ל־11 מהם השם מוסתר (`.is-dot`). נמדדה חפיפת מלבני האייקונים, בין היתר:

| צמד | שטח חפיפה |
|---|---:|
| האגם האקולוגי / גשרים ושבילים | 161.88px² |
| הפארק / גן משחקים | 49.91px² |
| גינת כלבים / גשרים ושבילים | 17.00px² |

לכן “0 נקודות ריקות” נכון במובן שהוחלפה הגרפיקה, אבל אינו מוכיח “שם ואייקון ללא חפיפה”. ב־320 יש גם אייקונים סמוכים לשפת הבמה או חתוכים על ידה.

המקור הספציפי ב־373: `labelCandidates`, שורה 2173, עדיין מגדיר `dotOnly` למתקנים במבט־על צר. `layoutLabels`, שורה 2323, עובר הלאה לפני הכנסת אייקון זה לרשימת המלבנים התפוסים. בענף אחר, שורה 2343, שם שלא נמצא לו מקום חוזר ל־`is-dot`.

```js
dotOnly: m === 'aerial' && narrow()
// layoutLabels, 373
if (c.dotOnly) { e.classList.add('is-dot'); continue; }
// Later: a failed label placement can also fall back to is-dot.
```

בקשה לסבב הבא: בחירה מפורשת בין (א) שם+אייקון כיחידה אחת עם collision לכל המשטח, לבין (ב) אייקון מקוצר, נגיש ומזוהה, רק כמצב מוצר שאושר בעיצוב. במצב א׳, פריט שנדחה אינו נעלם מהמידע: הוא נשאר ברשימה נגישה. אין להציג מצב ב׳ כאילו א׳ הושלם. להכניס גם את כפתורי המסך המלא/ייעוץ ל־reserved rectangles במפורש; hit-test תקין כרגע אינו הוכחה לכל זוויות המצלמה.

**עדכון 374:** יש בקוד טיפול חדש במלבני אייקונים; בדגימת HE320 הצפיפות ירדה, אבל `is-dot` ואייקונים ללא שם עדיין קיימים. לא בוצעה מטריצת collision מלאה כדי להכריז שכל החפיפות תוקנו.

### P1 / M15 — מפה יפה יותר, אבל עדיין צריך לעשות זום כדי לקרוא שמות

תיקון הסמלים השחורים עובד בצילומים שנבדקו: יש glyph לבן ברור בתוך צבע קטגוריה. קישור מתוך רשימת המקומות פתח popup של המקום על המפה. ב־EN/AR נותרה לעיתים כותרת גנרית School/مدرسة; ראו שפות.

אבל בצילום AR320 של 373 בזום 14.4 המפה מציגה אייקונים בלי שמות. ההשלמה ב־374 חזרה על כך ב־HE320, אחרי המתנה, כאשר style טעון, RTL טעון והמפה אינה בתנועה. ב־15.2 וב־16 הופיעו שמות. לא מספיק לראות `name` ב־GeoJSON או לספור `queryRenderedFeatures` כדי להוכיח שהטקסט מצויר. ספירת features יכולה גם לכלול כפילויות/פריטים סמוכים לגבול; אינני משתמשת בה כמספר שמות קריאים על המסך.

ראיית קוד בקובץ [areamap.js](../../plugins/nadlan-config/assets/arealife/areamap.js), שורות 277–290, ש־SHA שלו זהה ל־373:

```js
'text-field': ['step', ['zoom'], '', 14, ['get', 'name']],
'text-optional': false,
'icon-optional': false
```

מתחת ל־14 הקוד מבקש טקסט ריק במפורש, ולכן optional=false אינו יכול לייצר שם. היעדר השמות שנצפה גם ב־14.4 דורש בדיקת bucket/layout בפועל בגרסת Mapbox הפעילה; לא ייחסתי לו סיבה ודאית שלא נמדדה. אותה תמונה חזרה ב־374, ולכן אין כאן רק תזמון טעינה רגעי אחד.

לתיקון: מדגם מועט אך קריא של המקומות החשובים כבר בפריים הראשון, ולא עשרות אייקונים אנונימיים. לאפשר למנגנון collision לדחות את כל היחידה, בלי לכבות שמות בזום הפתיחה; כל היתר ברשימה. גם הנקודה הסגולה המרכזית נשארת בלי זיהוי גלוי — היא שייכת לשכבת marker נפרדת, לא לסמלי ה־POI שתוקנו. צריך לזהות אם זו נקודת הפרויקט/תוכנית ולתת לה שם מתאים, בלי לגעת במנוע האלומה הקפוא. סמלי GL אינם פותרים חפיפות מול כל HTML marker או פקד DOM. [Mapbox: label placement](https://docs.mapbox.com/help/dive-deeper/optimize-map-label-placement/).

### P2 / M19 — 24px ואייקון שאינו כפתור

תוויות האייקונים בעולם נמדדו 24×24px. ב־`labelEl` של 373, שורות 2249–2257, הסמל הוא `span.i` עם click listener, ואילו הטקסט הוא `button.t`. כשהטקסט מוסתר נשאר סמל שאין לו button semantics או תחנת Tab. זאת אינה רק בעיית גודל.

לתקן את רכיב האינטראקציה עצמו: כפתור עם שם נגיש, אזור מגע 44×44 לפחות, מוקד נראה והפעלת Enter/Space. האייקון המצויר יכול להישאר 20–24px. מנגנון ההתנגשויות חייב להגן גם על שטח הלחיצה המורחב, אחרת מרחיבים אותו ויוצרים חפיפות חדשות. לא מסמנים 44px ירוק מפני שהסרגל העליון בלבד עומד בו. מדובר גם בחוב שהמיישם כבר ציין במפורש, לא ברגרסיה חדשה שהוכח שנוצרה ב־373.

## 4. מה כן עובד ואסור לאבד

### הפאנל והיציאה — M02 / M09

- הפאנל נמצא בתוך `.nlw-dock`, מחוץ לבמה, עם `overflow-y:visible`; אין בו גלילה אנכית פנימית בדגימות שנשמרו.
- במרבית מקרי הקומה גובהו כ־486.8px; ב־EN320 כ־536.8px עקב התוכן. הגובה גדל במקום להפוך את התוכן לחלון פנימי.
- החלקה על הפאנל: העמוד נע 195px, המצלמה לא זזה. החלקה על כפתור כיוון: 135px; על שם בעולם: 115px; הבחירה לא השתנתה במדגם.
- הליכה בטלפון פותחת מסך מלא. יציאה בכפתור מחזירה ל־aerial ומחזירה את הפאנל ל־dock; בחירת C/30 נשמרה במקרים עם receipt מלא. לא בדקתי Back של מערכת הפעלה או מעבר אפליקציה.
- צילומי הפאנל נעשו אחרי גלילה מכוונת אליו כדי למדוד את רכיב התוכן. הם אינם ראיה שהבחירה עצמה מסתירה או מזיזה את הבניין.

### ייעוץ — M12

במסך המלא הכפתור החדש נגיש בחמש נקודות ה־hit-test שנמדדו. גובה 44px. רוחבים: עברית כ־107.8px, אנגלית 122.2px, ערבית 138.8px. גם היציאה 44×44 נגישה. אחרי יציאה הכפתור הגלובלי חוזר להיות עליון.

הכפתור הגלובלי עצמו נמצא מתחת למסך המלא, אבל יש תחליף פעיל בתוכו: זו אינה הוכחה שהייעוץ חסום. מנגד, זו בדיקת נראות/נגישות בלבד — לא בדיקת שליחה, מספר יעד או שימור unit/floor בהודעה בפועל. אין לקבוע שהקשר חסר רק כי `waFull.href=o.wa`: קיימת שכבת interceptor באתר, והיא לא נבחנה כאן עד לשליחה.

## 5. שפות ותוכן

### עברית

RTL וכיווני הכפתורים תקינים בדגימות. לא נצפתה עברית הפוכה. עדיין נראים ברשימת המקומות ערכים כמו `Open` וטקסט משולב כגון `נוצ'י סושי אנד,מחסן 15175`. זו בעיית נתוני שם/תצוגה, לא הוכחה לרגרסיה בספריית האייקונים. יש לנקות את שדה התצוגה תוך שמירת מקור הנתון, לא להמציא שם עסק.

### אנגלית

הסרגל מתורגם והעולם פועל ב־LTR. הביטויים `a facing`, `Dog garden`, `The great round square` אינם מספיק טבעיים לחוויה היוקרתית. הצעות: `orientation`, `Dog park`, וניסוח טבעי של `the circular square` בהקשר המשפט. אלו הצעות עריכה, לא שינוי שביצעתי.

ברשימת המפה שני בתי הספר הראשונים הופיעו בשם הגנרי `School`, בעוד בעברית מופיע שם ספציפי. עצם התרגום לקטגוריה אינו שומר את זהות המקום; צריך שם מקומי/תעתיק בשדה השם וקטגוריה נפרדת. ה־body עדיין נושא class בשם rtl גם בדף האנגלי; לא הסקתי מזה לבדו שהרינדור שגוי, כי לרכיבים יש כיווניות משלהם.

### ערבית

`من الأعلى`, `جولة سيراً`, `الطابق والإطلالة`, `بالجوار` ו־`استشارة مجانية` נראו בכיוון הנכון. המספרים ו־A/B/C נשארו ניתנים לקריאה. גם כאן שני בתי ספר מופיעים כ־`مدرسة` במקום שמם, ו־`Open` נשאר לא מתורגם. אין זו ביקורת לשונית מקיפה של עורך ערבית מקצועי; לא בדקתי את כל המאמר ואת כל ה־POI.

### 7.1 גלילה, כרטיס וייעוץ

בששת המקרים HE/EN/AR × 320/390:

- החלקה אנכית: scrollY השתנה ב־185px, שינוי quaternion אפס בדיוק החישוב. זהו תיקון מאומת לתרחיש הראשי של M01.
- החלקה על פאנל: 195px, שינוי מצלמה אפס.
- לחיצה אמיתית על שם מגדל פתחה כרטיס ב־dock. סגירה החזירה את הפאנל. אין גלילה אנכית פנימית בכרטיס שנבדק.
- גובה הבמה נשאר כ־489.52px בפתיחה ובסגירה; ההתרחבות היא מתחת לבמה.
- הליכה/יציאה והייעוץ עברו בחמש נקודות בדיקה בכל רוחב ושפה.

יש עדיין חיכוך UX: הכרטיס המלא שנפתח מגיע לכ־1065–1402px, בעיקר בגלל פירוט ומקורות חוזרים. בנוסף, לאחר סגירה המוקד נמצא ב־body במקום לחזור לכפתור שפתח אותו. המלצה: סיכום קצר ופעולה ראשית לפני פירוט מורחב, שמירת כל המידע מאחורי פרטים לפי נושא, והחזרת focus לטריגר. אין למחוק עובדות או מקורות כדי לקצר.

### 7.2 M24 / 1440 — גלגלת אחרי לחיצה עדיין נלכדת

| מצב | scrollY לאחר wheel של 260px | מצלמה |
|---|---:|---|
| לפני אינטראקציה בבמה | +260px | לא משתנה |
| אחרי לחיצה בבמה | 0px | מתרחקת / zoom |

זה אדום מול הקריטריון שנקבע ב־M24: לחיצה רגילה אינה אמורה ללכוד את גלילת ההמשך. הקוד מפעיל `controls.enableZoom=true` ב־pointerdown; איפוס בעקבות pointerleave אינו מבטיח שהמבקר יוכל להמשיך לגלול כשהמצביע נשאר בבמה. העיקרון קיים גם ב־373, אבל המדידה הזאת שייכת ל־374 בלבד.

המלצה: wheel רגיל נשאר גלילת עמוד במצב גלישה; zoom גלגלת רק במצב חקירה מפורש או עם modifier מוסכם ורמז. כפתורי +/− נשארים זמינים. לבדוק גם wheel קצר של trackpad ו־Ctrl+wheel, בלי לחסום זום דפדפן. דוגמת [Mapbox cooperative gestures](https://docs.mapbox.com/mapbox-gl-js/example/cooperative-gestures/) מועילה כמדיניות קלט; היא אינה הוראה להחליף את המנוע.

### 7.3 M19 — מבחן טקסט 200% מגלה חיתוך

מבחן דיאגנוסטי בלבד: הגדלת font-size של טקסטי הסרגל/הפאנל פי שניים בזיכרון העמוד, בלי שינוי CSS באתר. אחריו הוחזרו הגדלים. אין overflow של העמוד כולו, אבל יש overflow בתוך לשוניות:

| שפה, בשני הרוחבים | לשונית | scrollWidth / clientWidth |
|---|---|---:|
| HE | מה בסביבה | 125 / 109px |
| EN | Floor view | 127 / 92px |
| AR | الطابق والإطلالة | 143 / 103px |

כלומר, בדיקת `document.scrollWidth === innerWidth` לבדה תחמיץ חיתוך. יש לאפשר שתי שורות/גובה גמיש או פריסה חלופית שעוצבה במפורש, ולא להקטין שוב את הגופן. summary של הערות נמדד בגובה 35px במבחן הזה — גם הוא אינו יעד 44px מלא.

- חלון: לחיצה על הכיוון הראשון ב־HE320 הביאה ל־tower C / floor 30 / view=window / bearing≈356°. נראתה תווית תיאטרון עם אייקון. אין כאן הוכחת יחידה מדודה: `unit` נשאר ריק; הבחירה היא קומה/כיוון.
- מפה: HE320, זום 14.4, style loaded, RTL loaded, moving=false — אייקונים בלי שמות בצילום. ב־15.2 וב־16 נראו שמות. לכן החוזה “מידע ברור בלי להתאמץ ולעשות זום” עדיין לא הושג.

- אין אישור מקיף של כל 53 סוגי המקום/42 glyphs. רק הקטגוריות שנצפו נבדקו חזותית; רישיון האייקונים לא נסקר מחדש במסגרת QA זה.
