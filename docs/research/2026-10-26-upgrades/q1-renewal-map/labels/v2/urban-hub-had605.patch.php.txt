The finding (measured 26.10.2026 by the first labels proof): /renewal-lookup allows 30 calls per IP per hour, counted on every
call, including the same city asked again, and every counted call starts the hour again. Past that it answers 429 and every page that uses it prints "no complexes" for a city
that has complexes: the map's list ("אין מתחמים להצגה"), the pillar's lookup box and the wizard ("לא נמצא מתחם מוכרז תואם").
Israeli phone carriers put many visitors behind one public IP, so real visitors can hit the wall.

The fix:
- every answer is cached for 6 hours per city + query (the complex list changes only on an import); a cached answer is free
- the limit counts only calls the cache cannot answer, is 120 per IP (filter nadlan_ur_lookup_limit), and runs for a fixed hour
  from the first counted call; today every counted call sets the hour again, so a steady visitor or a carrier IP shared by
  many stays blocked until a full quiet hour passes
- past the limit: HTTP 429 with a Hebrew message and Retry-After, and the pillar's lookup box says so instead of "not found"
- the map v2 (urban-map-v2.patch.php.txt) no longer calls this endpoint while the tracker file is on the page

Same wrong message, outside this file (not patched here): assets/urban/renewal-3d.js, the renewal wizard, line 38:
    .then(function (r) { return r.json(); })
should become
    .then(function (r) { if (r.status === 429) throw { lim: 1 }; return r.json(); })
with its catch printing the same limit message instead of "".
