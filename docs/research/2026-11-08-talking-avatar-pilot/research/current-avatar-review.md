# HAD-682: current avatar technology review

Checked 7 November 2026. Requested freshness window: 31 October through 7 November 2026. This is a targeted comparison of leading relevant methods, not a claim to have tested every avatar or achieved worldwide best quality.

## Decision for this machine

Keep the approved blonde image and use the local Blender/GLB portrait as the immediately runnable baseline. Add an audio-driven, locally hosted viseme model for newly generated Chatterbox replies. Treat geometry, rendering, speech recognition, response generation, speech synthesis and turn timing as separate stages. A fast face renderer does not establish fast conversation.

The observed workstation has an AMD Ryzen 7 7730U, 8 cores/16 logical processors, AMD Radeon integrated graphics reporting 3 GiB, and 13,854,212,096 bytes of physical memory. These observations came from Windows CIM on 7 November. Most recent photoreal neural-video systems below target NVIDIA CUDA, often with substantially more GPU memory. They are useful quality references but are not drop-in free local runtimes here.

The MediaPipe-derived, photo-textured mesh is a **limited-view 3D portrait**. It has depth and deformable geometry; it does not reconstruct a verified back of the head, fully independent hair strands, changing skin illumination, or unobserved mouth interior. Keep yaw small and inspect both extrema. Do not describe it as a complete volumetric human or claim it surpasses the neural methods without an actual controlled comparison.

## Polish protocol applied to the local candidate

These are recommended acceptance checks, not claimed completed measurements:

1. **Identity:** compare neutral render with the original at 1:1 and actual display size. Preserve eyes, nose, mouth width, hair silhouette and face proportions. Do not beautify into a different woman.
2. **Mouth:** inspect bilabial closure, consonants, pauses and return to neutral. Smooth coefficient changes; clamp maximum aperture. Minimal movement still needs speech-correlated timing. Avoid jaw flapping from amplitude alone.
3. **Eyes and idle:** occasional brief blinks, stationary gaze and very small head motion. Avoid repeated symmetrical nod loops, constant eyebrow motion and constant smiling changes.
4. **Edges:** inspect hair against both white and dark page areas, both yaw extrema and motion frames. Reject halos, triangles appearing through the hair, torn lip seams and stretches at the neck.
5. **Interaction:** speech begins only following a trusted interaction. Closing must cancel playback and pending replies. Microphone permission follows an explicit mic action; denied permission produces a usable text fallback. Interrupting should stop old speech immediately.
6. **Performance:** measure frame time during actual speech, model bytes, memory pressure and dropped frames. Test 360px, 390px and desktop layouts with real page buttons. Stop rendering when closed or hidden.
7. **Conversation:** record uncut speech input to first audible reply, separating STT, retrieval/LLM and Chatterbox times. Short grounded answers and an honest thinking state beat pretending the CPU is instantaneous. The local service is a prototype backend, not a hosted production service.
8. **Evidence:** preserve each candidate, contact sheets, videos, parameter changes and test failures. A cropped showcase cannot establish overlay usability. A saved PNG cannot establish temporal stability.

Design continuity: NadLan Instruments ink `#0F2233`/`#12202A`, sea `#2F6F86`, mist `#D3DCE2`, IBM Plex Sans. This identity comes from the existing Claude Design export, not a new generic card system. No cream/gold accents or exaggerated character behavior are introduced by the avatar UI.

## What this research did and did not do

Actually performed: primary-source web research, official GitHub API checks across the date window, npm version/date inspection, local hardware inspection and source-file downloads with hashes. No commercial avatar was generated. The follow-on MIT 0.3.0 audio-to-viseme experiment is now implemented and measured; see [local-viseme-benchmark.md](local-viseme-benchmark.md). Its 11.8-second Chatterbox greeting took a median 0.848 seconds in Node and 0.865 seconds including decoding and worker setup in headless Chrome. This is not an end-to-end conversation latency figure. No production site change, key access, paid service or paid GPU was used by this research task.
