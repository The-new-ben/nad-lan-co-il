# Bounded resource wait and completed voice cache

This local source change keeps compact entry at 2.3 GiB physical / 2.5 GiB commit and active-process abort floors at 0.75 / 1.0 GiB. Before a compact stage, with no active owned child, admission may wait at most 30 seconds for both entry conditions. Cancellation and step/reply deadlines are checked every 0.1 seconds. Private admission records include outcome and wait duration. A compact reply's deadline includes time since job creation, bounded by 600 seconds.

Completed streamed speech can now be reused as one complete WAV. Cache identity includes exact answer text, model revision, original reference hash, implementation, both seeds, runtime, threads, greedy/repetition settings and per-sentence versus whole-reply watermark mode. Every question still follows the current model or reviewed fact route before an exact audio lookup. A hit has `voiceCacheHit:true`, `voiceGenerationPerformed:false`, zero voice-generation timing and no newly published chunks. It is reuse, not new synthesis.

Only a complete, validated output can enter the cache. Candidate metadata, complete sentences, stop tokens, WAV format/duration and audio hash are checked. Publication is deferred until owned-model cleanup succeeds. The final cancellation checkpoint, optional cache commit and public result/done publication share the existing lock. Cancellation observed before that checkpoint or a cleanup failure prevents success/cache admission. A later close after completed publication can cancel playback without invalidating a valid previously completed cache entry. Optional cache I/O failure does not invalidate already complete audio.

`research/prime_completed_voice_cache.py` defaults to verification only. Its sole source is the existing successful controlled `identity-02` reply. It pins full WAV and PCM hashes, independently concatenates the two actual chunk files and checks exact text and current voice metadata/profile. Only root's explicit `--go` adopts that verified existing output. No replacement question, answer or synthesis is generated by the helper.

Validation is in `evidence/compact-wait-cache-controls/final/receipt.json`: 38 checks, including virtual-clock 30-second exhaustion, cancellation/deadlines, recovery, active-child refusal, partial/cancelled reply exclusion, exact cache reuse without TTS, settings/text/watermark mismatch, and cleanup-publication races. An additional 34 earlier integration controls passed under `prior-controls/`; their direct admission-refusal checks used a zero-wait test override. Fixture voice operations copy the existing controlled reply only into isolated test caches. No model or browser was used, no server restarted and no production cache was primed by these checks.

Before-source copy: `evidence/compact-wait-cache-before/server.py`. Root retains ownership of live restart, actual cache adoption and any public test. The prior real public attempt failed stage admission before voice; this source change does not itself establish a completed public spoken reply.
