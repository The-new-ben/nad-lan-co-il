# Original MTL loader experiment

Prepared, compiled and independently statically reviewed. The coordinator invoked the guarded launcher once; its preflight stopped before starting a model because only1.4583GiB physical and1.6194GiB commit capacity were available. No inference or memory-saving measurement occurred. Evidence: `../evidence/original-mtl-loader-candidate/parent-receipt.json`. Preserve this failed preflight before a deliberate new attempt. No installed package, original server default, public asset or voice setting has changed.

`mtl_loader_candidate.py` uses the same installed Chatterbox Multilingual classes, ordinary CPU constructor order, pinned checkpoint, dtype and reference. It assigns checkpoint storage with strict `load_state_dict(..., assign=True)` and uses `mmap=True` for the existing ZIP checkpoints. Temporary source dictionaries are released before the next component. The original loader retains T3 checkpoint storage while constructing S3Gen and copies weights into already initialized tensors. The candidate removes these avoidable copies; its actual memory and latency remain unmeasured.

The installed PyTorch2.6 CPU source supports Windows mapped loading. The Windows restriction concerns changing mapping options. The [official PyTorch recipe](https://docs.pytorch.org/tutorials/recipes/recipes/module_load_state_dict_tips.html) explains mapped loading and assignment; the installed source was also inspected.

Blanket meta construction is deliberately excluded. Nonpersistent rotary/trim buffers and plain frequency/position/STFT tensors would need separate reconstruction. Meta would also skip ordinary initialization and change the random-generator state following seed682. The candidate preserves ordinary construction, then checks that checkpoint loading, value verification and assignment do not advance RNG state.

`benchmark_mtl_loader_candidate.py` is the only prepared launcher. Without `--go` it does not load a model. The explicit experiment requires at least6GiB physical availability and8GiB remaining commit capacity, distinct from the public original-voice admission requirements7.1/9.1GiB. It starts only its own hidden suspended child, assigns that process to the existing kill-on-close Windows job, then resumes it. The parent checks memory approximately every0.1s and cancels that owned tree at0.75GiB physical or1GiB commit. These intervals are sampling targets, not hard real-time guarantees. Health checks run in a separate thread, so HTTP cannot block memory monitoring. Original-server activity, unknown health, a local cancel file or420s deadline also stops the candidate.

The controlled first sentence is taken from the coordinator's public identity-question receipt: “I'm a fictional, computer-made guide.” It is not Ben's microphone input. The benchmark retains the original reference-conditionals cache, watermark path, seed682, four threads, English, exaggeration0.5, CFG0.5, temperature0.65 and silence trimming.

Artifacts will include source/reference/checkpoint SHA256 fingerprints, per-tensor key/dtype/shape/stride/value checks, storage identity and parameter-alias checks, recurrent flat-weight pointers, preserved nonpersistent/plain tensors, RNG binary snapshots, memory samples, OS peak counters and an audio file only if generation completes. Mapped tensor hashing occurs after assignment so old initialized weights do not coexist with a fully touched checkpoint merely for verification. Verification time is included in the reported load-and-verification total and separately broken down per component.

No claim of equal audio, listening approval, responsive conversation or a safe new public threshold follows from compiling this code. The original path's measured6.06GiB resident and8.09GiB commit peaks came from a canceled load, not completed speech. The experiment must finish and its evidence be reviewed before any adoption.
