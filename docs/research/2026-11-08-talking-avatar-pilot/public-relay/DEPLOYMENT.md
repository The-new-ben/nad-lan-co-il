# Prepared scoped relay deployment

The exact persistent Code Snippets name is **HAD682 NadLan one-page talk-back relay**. The script changes only that snippet and `nadlan_talk_enabled`. It does not edit page5154, the shared plugin, version607, analytics, DNS, assets or model processes. Root coordinates the independent page deployment.

`python deploy_relay.py` performs PHP lint, authenticated GET inspection and a local dry plan. Its read-only production run found no exact existing snippet. It does not create an endpoint to read the unregistered option during the dry plan.

Only the coordinator executes `python deploy_relay.py --go` after review. It installs a uniquely named temporary helper, reads and saves the prior exact snippet/option state, stages the reviewed PHP without its opening tag, activates and reads it back, enables the fixed option, verifies the public health route/no-store header, and removes the temporary helper in `finally`. Authentication reuses the existing private helper definitions; redirects are refused and credentials are never printed or saved in receipts. No worker starts automatically.

`python deploy_relay.py --disable` is also a dry plan. With `--go`, it sets that option false and deactivates only the exact named persistent snippet. This stops admission and makes the worker's next status request fail closed. It does not delete the reviewed persistent source or alter the widget/page. It is a disable operation, not a generic arbitrary-backup restore command.

Backups, plans and receipts go to `../evidence/public-relay/deployment/`. Backups preserve prior code, activation, writable snippet metadata, and whether the option existed. Failure recovery removes a newly created relay or restores its prior version, then restores the prior option when ownership of the current state can be established. A concurrent unexpected option edit is preserved and reported. The expected-state get/check/update is **best-effort, not an atomic database compare-and-swap**. A committed write with a lost response is recovered by fresh readback; simultaneous identical external writes cannot be distinguished. Review the receipt if rollback or temporary-helper cleanup is incomplete. No deployment is reported successful after failed cleanup.

Separately, the generated helper passed8/8 actual HTTP checks in the isolated WordPress7.1.3 fixture with real application-password authentication; its temporary local file was removed. The lifecycle tests are controlled response tests, not production execution evidence. Code Snippets' live route behavior still needs the coordinator's real execution/readback.

The preparation agent did not execute `--go` or perform any production write. This module being enabled does not prove Chatterbox availability, sufficient RAM, public microphone operation or conversational latency. Those require the actual worker and public end-to-end check.
