# Local relay contract, not enabled publicly

Base: `/wp-json/nadlan-talk/v1`. File: `nadlan-talk-relay.php`. Default `nadlan_talk_enabled=false`; the deployment owner alone enables the option after tests. No shared plugin, release version, page or remote account is changed by this module.

All browser calls are same-origin. `Referer` must be the exact `/en/buy-property-in-israel/` page on the configured WordPress home origin. GET `/session` returns `{ready,available,csrf,pollInterval:1000,maxRecordingSeconds:20,maxUploadBytes:15728640}` and a signed HttpOnly SameSite=Strict cookie (Secure on HTTPS). GET `/health` returns `{available,unavailableCode}`. Every browser POST needs the exact site Origin plus `X-NL-CSRF` from session. The CSRF value is session-bound, not the shared logged-out WordPress nonce. Session creation is limited to 60/10min per IP.

- POST `/converse`: `X-NL-Request-ID` of 16-80 alphanumeric/underscore/hyphen characters. JSON `{text}` up to1200 characters, or multipart `audio` plus `duration` seconds, positive and <=20. Entire body <=15MiB. Worker MUST check actual decoded duration before submitting to local inference; the client hint is not proof. MIME accepted audio/webm, audio/mp4, audio/ogg, audio/wav, audio/x-wav. Acknowledges202 with `jobId,requestId,phase,jobUrl,expiresAt,deadlineAt,chunks`.
- GET `/jobs/{jobId}` returns cumulative chunks and final `result` using the existing client convention. Only the same visitor may poll or play audio.
- POST `/requests/{token}/cancel` remembers cancellation before registration; POST `/jobs/{jobId}/cancel` cancels a known job. Both remove saved input/output immediately and prevent late publication. New questions replace that visitor's pending answer only.
- GET `/audio/{jobId}/{index|full}` returns authorized WAV bytes, private/no-store. No uploaded or generated audio enters public WordPress media. No public prewarm route exists.

Worker endpoints require WordPress application-password Basic authentication for an existing administrator, verified by `rest_get_authenticated_app_password()` and `manage_options`. Browser cookie/nonces cannot authenticate workers. Credentials stay in the existing script-only path. The existing deployment helper is `C:/Users/777/nad-lan/nad-lan-co-il/scripts/skin-a/deployskin.py`; `docs/research/2026-11-07-talking-agent/deploy_live.py` shows how it loads only the helper prefix. Do not execute its deployment body or print its credential variables.

- POST `/worker/claim` JSON `{workerId,ready,unavailableCode?}`. workerId8-64 alphanumeric/underscore/hyphen. ready=false updates availability and never claims work. unavailableCode is resource_busy or local_unavailable. Returns `{job:null}` or `{job:{jobId,leaseToken,ownerKey,requestId,text,mime,durationHint,audioBase64?,deadlineAt,expiresAt,leaseUntil,cancelled:false,maxRecordingSeconds:20}}`. audioBase64 is the original upload. Only one leased job globally. Each ownerKey MUST have a separate local cookie jar/history; pass requestId to the local API.
- GET `/worker/jobs/{jobId}` with `X-NL-Lease` header returns `{cancelled,phase,deadlineAt,leaseUntil}`. Do not put lease credentials in the URL. It does not renew the lease.
- POST `/worker/jobs/{jobId}/update`, with `leaseToken` in JSON (or X-NL-Lease), and event:
  - heartbeat: renew every15seconds or sooner. Lease45seconds, capped by request deadline600seconds.
  - progress: phase transcribing/thinking/synthesizing/streaming; optional userText,responseText,inputConsumed. inputConsumed deletes saved uploaded bytes.
  - chunk: flat index,text,audioBase64,duration. WAV <=4MiB, indices0..7 sequential; exact repeated bytes+text are idempotent; changed published content rejected. Cues are currently empty for browser learned analysis.
  - done: complete combined WAV audioBase64,text,duration,voiceEngine,voiceCacheHit. The combined file is required for complete-answer replay. This may be the only audio event for a non-streaming answer.
  - error: errorCode resource_busy or failed. Public messages are fixed; internal exceptions and paths are never forwarded.
- Updates normally return `{accepted:true,cancelled:false,phase,leaseUntil,deadlineAt}`. Cancelled/error/done terminal jobs reject further writes with409 and `{accepted:false,cancelled,phase}`. Missing/incorrect leases404. Stop local work immediately on cancellation/deadline/lost lease; never republish stale audio.

Jobs expire after900seconds. Metadata/input/audio live only in private transients; binary audio is base64 encoded for safe text-database storage. Cleanup removes expired payloads when relay requests acquire the queue lock, and WordPress also cleans expired database transients on its normal schedule. Expiry denies access immediately; physical deletion is request/cron driven, not an exact wall-clock guarantee when the site stops receiving requests. One active job plus four waiting capacity slots globally; queue/claim/state changes use an atomic WordPress option lock. Per-session starts6/10min, per-IP20/hour, global60/hour are bounded pilot admission limits, not throughput claims. At most128 retained job IDs and128MiB raw payload bytes (base64 storage overhead is additional). No job can be accepted unless enabled and a ready worker heartbeat was seen in the last30seconds. Worker polling should back off when idle. The plugin has no model, external provider or paid fallback. Success and failure responses in this namespace are no-store; page/analytics settings are unchanged.

The initial implementation is still under real WordPress testing. Authentication, concurrency and payload limits must pass before publishing. This document is a contract, not evidence that a public conversation is working.
