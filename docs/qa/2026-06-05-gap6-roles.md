# GAP 6 roles QA - v1.45.0

Branch: `codex/gap6-roles`  
Scope: plugin lane only, `plugins/nadlan-config/**` and `docs/**`  
Primary source: `docs/agent-comms/claude-codex-channel.md`, GAP6 directive at UTC 2026-06-05 09:05

## What changed

- Added `inc/roles.php` with `NADLAN_ROLES_VERSION = 1`.
- Added `nadlan_advertiser` with primitive listing caps only: `read`, `edit_listings`, `edit_published_listings`, `publish_listings`, `delete_listings`, `upload_files`.
- Added `nadlan_buyer` with `read` only.
- Granted administrators the custom listing management primitives and `manage_advertisers`.
- Added idempotent setup through activation plus a gated `admin_init` update path.
- Added uninstall cleanup for custom caps and custom roles only. Core caps like `read` and `upload_files` are not removed from existing roles.
- Added a version-gated migration that assigns users with owned cards to `nadlan_advertiser` and other users to `nadlan_buyer`.
- Added `capability_type => array( 'listing', 'listings' )`, `map_meta_cap => true`, and the listing capability map to `nadlan_property`, `nadlan_project`, and `nadlan_professional`.
- Changed listing REST meta writes from broad `edit_posts` to `current_user_can( 'edit_post', $post_id )`.
- Changed Studio edit authorization to `current_user_can( 'edit_post', $post_id )`, so ownership runs through `map_meta_cap`.
- Claim approvals and Studio-created listings now assign the advertiser role immediately.
- Healthcheck now reports `roles.version`, `roles.nadlan_advertisers`, and `roles.nadlan_buyers`.

## Capability model

Custom listing CPTs use WordPress' native cap flow:

- Meta cap: `edit_post` with a listing ID.
- Primitive caps: `edit_listings`, `edit_published_listings`, `publish_listings`, `delete_listings`, and administrator-only `edit_others_listings`.
- Ownership source of truth remains `owner_user_id` plus `claim_status=verified`.
- `nadlan_claim_map_meta_cap()` continues to grant owners access only to their own verified listing.
- Non-owners must have `edit_others_listings`; the advertiser role deliberately does not have it.

## WP-CLI proof script

These commands are intended for Claude/live sandbox because this local Windows environment does not have PHP/WP-CLI available.

```bash
wp eval 'nadlan_roles_setup(); nadlan_roles_setup(); echo (int) get_option("nadlan_roles_version");'
```

Expected: `1`; the second setup call performs no migration or role rewrite because the version gate returns early.

```bash
wp role list
wp cap list nadlan_advertiser
wp cap list nadlan_buyer
wp cap list administrator | grep -E "edit_listings|edit_others_listings|publish_listings|delete_listings|manage_advertisers"
```

Expected:

- `nadlan_advertiser` exists and has no `edit_others_listings`.
- `nadlan_buyer` exists with `read` only.
- `administrator` has all management caps.

```bash
wp eval '
$owner = wp_create_user("gap6_owner", wp_generate_password(), "gap6_owner@example.test");
$other = wp_create_user("gap6_other", wp_generate_password(), "gap6_other@example.test");
$card = wp_insert_post(array("post_type"=>"nadlan_project","post_status"=>"publish","post_title"=>"GAP6 owner test","post_author"=>$owner));
update_post_meta($card, "owner_user_id", $owner);
update_post_meta($card, "claim_status", "verified");
nadlan_roles_assign_user($owner, true);
nadlan_roles_assign_user($other, false);
echo "owner=" . (user_can($owner, "edit_post", $card) ? "yes" : "no") . "\n";
echo "other=" . (user_can($other, "edit_post", $card) ? "yes" : "no") . "\n";
echo "admin=" . (current_user_can("manage_options") ? "ready" : "manual") . "\n";
'
```

Expected:

- `owner=yes`
- `other=no`
- Admin can edit through `edit_others_listings` after setup.
