# Showroom Core 1.68.0 QA

## Scope

Plugin release `1.68.0` fixes the showroom core defects visible on the current live pages:

- building camera defaults to horizontal orbit, not full vertical tumble;
- the legacy CSS tower/facade is not emitted when a GLB + fixed facade are active;
- showroom failures are visible, not silently replaced by old fallback layers;
- the fixed facade picker can be dismissed and restored;
- mobile no longer keeps the model, facade picker and apartment card fighting in the same overlay layer;
- CMS fields exist for camera behavior, facade images, site plan image and site-plan polygons.

## Human Visual Findings

- Desktop is structurally usable: the GLB context and fixed facade are visible side-by-side.
- Mobile current-live is not good enough: the fixed facade sits over the 3D model and the selected-apartment sheet competes below it.
- The automated script still passes because there is no horizontal overflow and tap targets are large enough. That is why screenshots are mandatory: geometry can pass while the composition still feels wrong.
- Owner load-phase finding: the new fixed facade appears first, then the old fallback facade/tower can reappear after the model/runtime load state changes. The `1.68.0` fix now stops emitting the legacy `<figure class="nlp3d-facade">` markup when the embedded showroom surface is active. Model failure now shows `.nlp3d-model-error` instead of silently resurrecting the old tower/facade.
