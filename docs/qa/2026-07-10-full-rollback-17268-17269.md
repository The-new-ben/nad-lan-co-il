# NadLan Config 1.72.70 Full Behavioral Rollback

## Decision

The owner explicitly authorized a full rollback of releases 1.72.68 and 1.72.69 after the
Rainbow composition change removed established buyer capabilities and changed shared showroom
behavior on other project pages. The rollback is shipped forward as 1.72.70 so WordPress treats
it as a normal upgrade. It is not deployed as a version downgrade.

## Exact Boundary

- Pre-change parent: `de1fca8`
- Reverted release commit: `f16ef72` (`1.72.68`)
- Reverted dependent polish commit: `141f6ed` (`1.72.69`)
- Rollback branch: `codex/revert-17268-17269`
- Forward release: `1.72.70`

Historical QA reports, screenshots and the 1.72.68/1.72.69 packages remain available as audit
evidence. They are not referenced by the 1.72.70 update manifest.

## Why The Rollback Was Required

Release 1.72.68 used broad early returns to suppress whole legacy project modules when Rainbow's
composition flag was enabled. The replacement engine did not contain all of those capabilities.
On Rainbow this removed the unified map directly under the theater, the apartment direction cone,
financing, advisors, professionals, facts, gallery, project links and buyer resources. It also
changed camera and mobile behavior globally for Ashira, Dimri Yama, DUO and every engine project.
Release 1.72.69 depended on that composition and therefore cannot remain independently.

## Runtime Behavior Restored

- One-map doctrine: `#nlpjx-map` sits directly under the 3D theater and the generic `.nl-map` is
  hidden after adoption.
- Apartment selection rotates the map and draws the established direction cone.
- Price/world sections, financing, advisors, professionals and lower buyer-resource links return.
- Project facts, gallery, source/profile links, social links and project video return when data is
  present.
- The pre-1.72.68 model orbit limits, auto-rotation delay and speed return for all projects.
- The pre-1.72.68 mobile drawer dimensions and close control return.
- Selecting an inventory card no longer forces a scroll back to the theater.
- A model error no longer automatically changes the buyer's selected view.
- The 1.72.68 global translation override is removed.

## Rainbow Data Rollback

The five Rainbow language posts are restored from
`docs/qa/rainbow-17268-meta-backup.json` using
`scripts/rainbow-composition-meta.mjs --rollback`. The restored keys are:

- `project_model_glb`
- `project_3d_units`
- `project_3d_drawings_json`
- `nadlan_showroom_composed_v2`

This returns each language page to its exact pre-migration values rather than guessing URLs or
editing JSON by hand.

## Release Procedure

1. Reverse `141f6ed`, then reverse `f16ef72`.
2. Preserve unrelated working-tree files and historical QA evidence.
3. Set every version surface and the manifest download URL to 1.72.70.
4. Build only with `scripts/build-plugin-zip.py`.
5. Verify PHP syntax, JavaScript syntax, ZIP paths, CRC, manifest and embedded version strings.
6. Merge the reviewed rollback to `main`.
7. Restore the five Rainbow metadata records from the committed backup.
8. Deploy through the temporary admin-gated updater route and remove the route immediately.
9. Clear caches and independently verify the public healthcheck.
10. In Chrome, verify Rainbow, Ashira, Dimri Yama and DUO at desktop and mobile widths.

## Anti-Stack Statement

This release adds no renderer, map, content wrapper or CSS layer. It removes the composed-mode
suppression and replacement code and restores the known pre-1.72.68 renderer contract. The live
gate must prove one `#nl-root`, zero `.nlv2-showroom`, one unified project map and a hidden generic
engine map. Historical duplicate-H1 behavior on Dimri Yama and DUO is a pre-existing condition and
will be reported honestly rather than silently changed inside this rollback.

## Reversal Of This Rollback

If the owner later chooses to reintroduce the composition, the exact 1.72.68 and 1.72.69 commits,
packages, metadata backup and migration script are retained in Git history. Reintroduction must be
capability-by-capability, with a parity matrix proving that no existing buyer feature is suppressed
until its replacement is present and browser-verified.
