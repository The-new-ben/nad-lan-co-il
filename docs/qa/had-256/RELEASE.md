## The private photo folder

**Chosen: a guarded define at the top of the 707 body** (`PRIVATE_PRELUDE`):
`if ( ! defined( 'NL_OWNER_PRIVATE_DIR' ) ) { define( 'NL_OWNER_PRIVATE_DIR', rtrim( dirname( ABSPATH ), '/' ) . '/nl-private' ); }`.
Why: owner-wizard reads the constant only inside `nl_owner_private_base()`, i.e. while serving a request, long after
any snippet loads, so the snippet itself is early enough; wp-config.php is not touched and a define there still wins;
the setting ships, rolls back and re-releases together with the code that uses it (a rollback restores the 1.0 body,
which never reads it). The runner makes the folder, proves it writable, outside ABSPATH and the document root, writes a
test file and GETs `/nl-private/<f>`, `/../nl-private/<f>`, `/wp-content/nl-private/<f>`, `/wp-content/uploads/nl-private/<f>`
(and the document-root path if it were inside): none may carry the test file's words; then removes the test file. After
the write it checks that the live snippet now defines exactly that folder.

## What the runner does

`python scripts/had-256/deploy_had256.py --package 202 --page B --dry` first, then the same without `--dry`.
`--rollback docs/qa/had-256/live-backup/<UTC>` undoes a release. Steps:
1. **Lock + health, its own step**: the last `RELEASE ` line of the MAIN repo's `docs/coordination/claude-codex.md` must
   be DONE or ROLLED BACK; this release's own record must not be in flight; `/wp-json/nadlan/v1/health` status ok; no
   other `x-tmp-*-ops-*` bridge active (it refuses, it never sweeps another run's bridge). It prints the IN PROGRESS line
   to append.
2. **Read**: snippet 707 (must be named x-owner-wizard) and the one snippet named x-broker-drop; refuses unless they are
   exactly the bases above and active; "already carries this package" exits clean.
3. **Backup before anything else**: both bodies byte for byte + `snippets.json` (ids, names, active, scope, hashes) to
   `docs/qa/had-256/live-backup/<UTC>/` (with a `.gitattributes` `* -text`, so git never rewrites their line ends; the
   rollback also accepts an LF/CRLF-converted copy whose LF text matches).
4. **Build + lint**: the package bodies, `php -l` locally, then the bridge's `lint_code` on the server's PHP; the page
   read (must be page 4958) and saved to the backup; variant applied.
5. **Private folder** (above). `--dry` only checks (no folder made, no file written).
6. **Write**: x-broker-drop first, then 707 (PUT inactive + activate, read back, hash and active compared), then the page
   (only over the expected text). From the first write on, ANY failure (a check, a FATAL, a network error, a stop from
   outside) triggers the automatic rollback before the bridge goes down.
7. **Purge** (LiteSpeed all, object cache, OPcache).
8. **Checks**, cache-busted then plain, a second round after another purge: the prelude's folder constant; `/post-listing/`
   and `?lang=en` (need: the app section with `data-v="<version>"`, `<style id="nlj-css">`, `<script id="nlj-js">`,
   `"engine":true`, `"v":"<version>"`, header, footer, `#nlcta`, `#nla11y-btn`, exactly one H1, the Hebrew H1 / the English
   shell; `<meta name='robots' content='index, follow`; with B the new paragraph; never: the 1.0 gate `id="nlow-gate"`,
   `nlowg-go`, `"engine":false`, `nadlan-pwiz`, bench words, `>nl-drop-`, `Fatal error`, with 2.0.2 `class="nlpub-how"`
   and the old promise "עם כפתורי וואטסאפ וחיוג אליכם"); `/brokers/meital-katzir/` and `/en/brokers/meital-katzir/`
   (200, one H1, the same `nlb-lcard` count as just before the write); `/properties/nofei-yam-3-rooms-balcony-for-rent/`
   (200, one H1, its H1 text, `class="nlx-plate"`, the broker's `wa.me`); the healthcheck (owner version, engine true,
   sealed true, x-broker-drop 1.1.4); `POST /listing-submit` 410, anonymous `POST /owner/draft` 401, a dead drop link 404.
   A failure after the second round: the automatic rollback (707 first, then the engine, then the page; purge; the
   rollback checks: the 1.0 gate back, no app, broker cards as before, healthcheck versions printed).
9. **Bridge down**: deactivate, delete, the route must answer 404 (printed). Record: `docs/qa/had-256/deploy-result-had256.json`.

Credentials: deployskin.py's prefix (DPAPI app password, in-process, never printed), loaded exactly as
`upload_project_films.py` does. `--bench` mode never loads it (loopback addresses only).
