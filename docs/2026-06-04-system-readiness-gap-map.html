The plumbing exists. The two pipes that print money are not connected.

A customer can browse, see premium cards, and now pay (cart/checkout unblocked today). But paying does not actually move you up the results, and there is no auto-renew — so it is not yet a hands-off subscription business. Plus the AI agents are wired to the wrong vendor (Anthropic, you have OpenAI).

Cycle 4 · The gaps to close (in priority order)

Exactly what to build, where, and how

GAP 1 · Paid placement does not boost rank REVENUE-CRITICAL

File: plugins/nadlan-config/inc/directory.php · Lines: 76-86 & 560-570 · Effort: ~1 hr

The "featured" sort orders by menu_order then date — it never reads paid_tier. So Pro/Premier buyers get a badge but the same position. The core promise ("pay to be seen first") is unfulfilled.

// directory.php — replace the 'featured' branch of nadlan_dir_query()
case 'featured':
default:
  // rank premier(2) > pro(1) > free(0), then newest
  add_filter('posts_clauses', 'nadlan_tier_rank_clauses');
  $args['orderby'] = 'menu_order date';  // placeholder; clause injects tier
  break;

// new helper: inject a computed tier-rank ORDER BY (LEFT JOIN postmeta)
function nadlan_tier_rank_clauses($c){ global $wpdb;
  $c['join']    .= " LEFT JOIN {$wpdb->postmeta} tr ON tr.post_id={$wpdb->posts}.ID AND tr.meta_key='paid_tier' ";
  $c['orderby']  = " FIELD(tr.meta_value,'premier','pro') DESC, {$wpdb->posts}.post_date DESC ";
  return $c; }
Pattern is industry-standard — Directorist "Rank Featured" + Classified-Listing "Top Ads" do exactly this. Sources: Directorist Rank Featured · Classified Listing features

GAP 2 · No auto-renew → not a hands-off subscription REVENUE-CRITICAL

Files: advertiser-orders.php:15-18,103-140 · Effort: 1-2 days (gateway-dependent)

Products charge once (476=30d, 477=30d, 489=180d, 490=60d → advertiser-orders.php:15-18), set campaign_end, and a daily cron downgrades to free. There is no recurring charge. "People subscribe, fully automatic" requires one of:

// OPTION A (fastest, zero new gateway): sell ANNUAL SKUs + a 7-day
// pre-expiry email that links straight back to /cart/?add-to-cart=PID
add_action('nadlan_ao_daily_downgrade', 'nadlan_renewal_reminder', 5);

// OPTION B (true auto-renew): integrate a subscriptions plugin and verify
// Morning/Green-Invoice supports tokenized recurring charges.
Ready GitHub: wpswings/subscriptions-for-woocommerce (free, auto-renew) · free alts: YITH / Flexible Subscriptions. Blocker to verify: does the Morning gateway tokenize cards for recurring? If not → Option A (annual + reminder) is the zero-risk path.

GAP 3 · AI agents wired to Anthropic; you have OpenAI YOU ASKED FOR THIS

Files: ai-concierge.php:179-187, ai-features.php:53-58 · Effort: ~half day

The concierge already has RAG over glossary/directory + lead capture — only the HTTP call targets api.anthropic.com. Add an OpenAI adapter and a provider switch; everything else (the avatar widget, the talking-to-customers vision) builds on top of this.

// ai-concierge.php — add provider switch (option nadlan_ai_provider)
$provider = get_option('nadlan_ai_provider','openai');
if ($provider==='openai'){
  $resp = wp_remote_post('https://api.openai.com/v1/chat/completions', [
    'headers' => ['Authorization'=>'Bearer '.get_option('nadlan_ai_openai_key'),
                  'Content-Type'=>'application/json'],
    'body' => wp_json_encode(['model'=>'gpt-4o-mini','messages'=>$messages]) ]);
}
For the "talking avatar from inside the project" vision: open-source widget widgetplatform/widget-oa (OpenAI Assistants) · multi-provider RAG reference AskAny. Avatar/voice = later phase (ElevenLabs/HeyGen) once the text agent is on OpenAI.

GAP 4 · Advertiser doesn't auto-receive their own leads VALUE

File: conversion-cta.php:97-115 · Effort: ~2 hrs

A lead on a Pro/Premier card stores lead_card_id but only emails the site admin. The paying advertiser never gets it — so they pay and see nothing. Add: if the card has an owner_user_id and tier ≥ pro, email/notify that owner too.

// after the lead is saved in conversion-cta.php
$owner = (int) get_post_meta($card_id,'owner_user_id',true);
$tier  = get_post_meta($card_id,'paid_tier',true);
if ($owner && in_array($tier,['pro','premier'],true)) {
  wp_mail(get_userdata($owner)->user_email, 'פנייה חדשה לכרטיס שלך', $body);
}

GAP 5 · No geo-radius search GROWTH

New module: inc/geo-search.php · uses existing lat/lng meta · Effort: ~1 day

We already store lat/lng on every card. Drop in a Haversine geo_query so the directory REST can answer "within X km of a point."

Ready GitHub (drop-in, uses post-meta lat/lng like ours): birgire/geo-query (Haversine, WP_Query geo_query param) · jhackett1/wp-geo-search · full UI: GEO my WP

GAP 6 · No role/authority system OPERATIONS

New module: inc/roles.php · Effort: ~1 day

Everything is admin-or-owner. To run zero-touch with delegated staff/agents you need real roles: nadlan_advertiser (manage own cards only), nadlan_manager (moderate + reassign, no billing), plus capability checks replacing the blunt manage_options gates (studio-rest.php:28, tiers.php:216, etc.).
