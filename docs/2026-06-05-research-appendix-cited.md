## A. SAFE RELEASE / DEPLOY INFRASTRUCTURE (Phase 0) — 17 sources
Key rules we will implement:
- **Feature flags via a single decision layer** reading `get_option('nadlan_features')`; business code receives the decision, never queries inline. Separate RELEASE toggles (short-lived) from KILL SWITCHES (operator-flipped, no redeploy). Keep flags short-lived; track removal (toggle-debt → Knight Capital $460M). (Fowler https://martinfowler.com/articles/feature-toggles.html , https://martinfowler.com/bliki/DarkLaunching.html)
- **Staging-first**: Dev→Staging→Prod; copy DB DOWN from prod, push CODE up; never push staging DB onto prod. (WP Engine https://wpengine.com/support/development-workflow-best-practices/ , https://wpengine.com/support/copy-site/)
- **Versioned idempotent migrations**: store `nadlan_db_version`, run on mismatch; `dbDelta()` can't drop/rename and can lie — verify; never destructive on update. **Expand/Contract** for breaking changes (add new, write both, backfill, switch reads, drop old in a LATER release) — this is what makes rollback safe. (https://developer.wordpress.org/reference/functions/dbdelta/ , https://blog.thepete.net/blog/2023/12/05/expand/contract-making-a-breaking-change-without-a-big-bang/ , https://wpmayor.com/how-to-write-a-plugin-upgrade-routine/)
- **Rollback**: keep prior ZIP per release tag; `wp plugin update nadlan-config --version=X`; WP Rollback UI; out-of-band = `wp plugin deactivate` / SFTP folder-rename (WP auto-deactivates a plugin whose folder vanishes). (https://www.liquidweb.com/wordpress/development/rollback-plugin-theme/ , https://docs.wprollback.com/plugin-rollbacks , https://developer.wordpress.org/cli/commands/plugin/deactivate/)
- **WP fatal-error protection** (since 5.2) pauses the offending plugin + emails a recovery link; needs DB, skips mu-plugins; override via `fatal-error-handler.php` drop-in. We add our OWN per-module try/guard so one bad module auto-disables instead of white-screening. (https://make.wordpress.org/core/2019/03/20/the-improved-fatal-error-protection/ , https://wordpress.org/documentation/article/recovery-mode/)
- **Release gate = brutally pass/fail**: lint + static + CVE scan → fast smoke + HTTP health probe → checklist (migrations, secrets, deps, metrics, rollback plan, sign-off) → rehearse rollback as a drill. (https://oneuptime.com/blog/post/2026-01-30-deployment-gates/view , https://www.harness.io/harness-devops-academy/integrating-smoke-testing-into-your-ci-cd-pipeline-what-devops-needs-to-know , https://octopus.com/devops/software-deployments/deployment-checklist/)
- **Secrets**: keys from env/`wp-config` constants, not code/options; `WP_ENVIRONMENT_TYPE` selects test vs live keys; never commit salts. (https://developer.wordpress.org/apis/wp-config-php/)

## B. AUTONOMOUS LEAD→MONEY LOOP + WHATSAPP (Chunks B/C/G) — 14 sources
~80% automatable as an idempotent, audited STATE MACHINE; 4 human/owner gates remain.
- **Inbound**: Meta WhatsApp Cloud API webhook (`entry[].changes[].value.messages[]`); handle `statuses[]` too. The **24-hour window** governs everything (free-form only inside; pre-approved templates outside). **Explicit opt-in mandatory**; **quality tiers** throttle (start ~1k/24h). Frame transactional follow-ups (confirmations, invoices) as **Utility templates** (free in-window since Jul 2025). (https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/send-messages , https://www.twilio.com/docs/whatsapp/key-concepts , https://help.twilio.com/articles/30304057900699-Notice-Changes-to-WhatsApp-s-Pricing-July-2025)
- **Respond within 5 MINUTES** — 21× more likely to qualify, 100× to contact (MIT/InsideSales). The whole reason for an always-on agent. (https://caseyresponse.com/blog/lead-response-time-statistics)
- **Qualify on a fixed schema** (budget/intent/timeline), score+route; ground answers in listings; human-handoff gate on low confidence / negotiation / "talk to a person".
- **Booking**: Calendly/Cal.com API create-booking + webhook as source of truth; calendar event id = idempotency key. Appointment can be autonomous; **a real deal/lease close cannot** (negotiation/signature = human). (https://developer.calendly.com/api-docs , https://cal.com/docs/developing/guides/automation/webhooks)
- **Charge+Invoice**: recurring via Morning standing order; one-off via WooCommerce + Morning-for-Woo auto-issues the legal invoice **on the PAID event** (not order-created). **Israeli tax docs are immutable** → charge→invoice must be the MOST idempotent step (double-fire = real accounting problem). (https://greeninvoice.docs.apiary.io/ , https://wordpress.org/plugins/wc-gateway-greeninvoice/ , https://developer.woocommerce.com/docs/best-practices/urls-and-routing/webhooks/)
- **Orchestration**: assume every webhook fires >once → dedupe on delivery-id/resource-id; Action Scheduler queue with per-cycle idempotency key + lock (charge at most once/cycle); own your idempotency table (don't trust platform dedupe — Woo #26851). Append-only audit log of every transition. (https://deepwiki.com/woocommerce/action-scheduler , https://github.com/woocommerce/woocommerce/issues/26851)
- **HONEST GATES (must stay human/owner)**: deal close/negotiation; money authorization on real deals; identity/KYC; **referral fees = RESPA legal landmine** (12 CFR §1024.14, "thing of value" is broad — legal review before ANY referral payout). (https://www.consumerfinance.gov/rules-policy/regulations/1024/14/)

## C. ADMIN CONTROL PLANE (Chunk E) — 12 sources
- **Edit client meta safely**: meta box save = nonce → autosave-bail → `current_user_can('edit_post',$id)` → sanitize (`sanitize_text_field`, `esc_url_raw`, clamp lat −90..90 / lng −180..180 / weight 0..100) → `update_post_meta`. REST: `register_meta` with `sanitize_callback` + `auth_callback`. Gate the SCREEN behind a custom cap `manage_marketplace_clients`. (https://developer.wordpress.org/reference/functions/add_meta_box/ , https://developer.wordpress.org/reference/functions/register_meta/)
- **Placement/competition overrides**: store as SEPARATE signals (`is_pinned`, `boost_multiplier`, `reserved_slot`, `promo_until`) resolved at query time — never mutate the organic score in place; boost amplifies within the ranker, doesn't replace it; reserve pinned slots out-of-band; **time-box every override** (auto-expire). (https://innovation.ebayinc.com/stories/ebay-makes-promoted-listings-in-search-results-more-relevant-and-dynamic/ , https://sellermetrics.app/amazon-product-listing-optimization/)
- **Safe impersonation**: log start/end as distinct events; tag every action "Impersonated By <operator>"; never record as the client's own unattributed action; persistent banner + max duration + explicit stop; prefer read-only. (https://collegium.pathify.com/external/pages/best-practices-for-user-impersonations)
- **Audit log**: who/what/when/where + OLD→NEW value; tamper-evident, append-only, clock-synced; **never log secrets/PII**; separate from app logs; retention to strictest regime. Mandatory-audit events: permission/billing/export/config/admin-access. (https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html , https://www.sonarsource.com/resources/library/audit-logging/)
- **RBAC**: least-privilege `client_operator` distinct from owner/super-admin; separation of duties (editor of placement ≠ approver of billing); role hierarchy/inheritance; map to NIST AC-2/3/5. (https://blog.securelayer7.net/role-based-access-control/ , https://hoop.dev/blog/nist-800-53-database-roles-implementing-least-privilege-and-strong-separation-of-duties/)
- **Operator UX**: bulk = prefer UNDO toast over modal; reserve confirm-friction (type-to-confirm) for destructive/irreversible; don't over-confirm; scoped search/filter before bulk. (https://www.eleken.co/blog-posts/bulk-actions-ux , https://medium.com/design-bootcamp/a-ux-guide-to-destructive-actions-their-use-cases-and-best-practices-f1d8a9478d03)
